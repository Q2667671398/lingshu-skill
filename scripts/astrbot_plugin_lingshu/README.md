# 灵枢跨环境记忆桥 · 本地修订 v0.2.1

适配目标：AstrBot `>=4.13.0,<5.0.0` 的 Windows、Linux、macOS、Docker/远程部署。使用宿主现有 Python，不需要 DSH、Node、Ollama 或新增第三方 Python 依赖。实际运行测试仅完成 Windows Python 3.12；其他平台和真实 AstrBot 仍须验收。

## 安装

1. 在 AstrBot 插件管理中上传 `astrbot_plugin_lingshu-0.2.1-portable.zip`，或将本目录完整复制到 `data/plugins/astrbot_plugin_lingshu/` 后加载。不要把最外层的原始技能 ZIP 当成 AstrBot 插件上传。
2. 默认配置留空即可使用包内核心。`lingshu_path` 指向包含 `scripts/brain.py` 的目录；自定义核心必须是本修订版，否则隔离修复不会生效。
3. 默认数据在 `data/plugin_data/astrbot_plugin_lingshu/memory`。Docker 的 `data` 必须持久化到宿主机；容器内配置只能填写容器内路径。一般沿用 AstrBot 官方 `./data:/AstrBot/data` 挂载即可。
4. 加载后私聊执行 `lingshu 状态`，再执行 `lingshu 身份`、`lingshu 记住 我喜欢绿茶`、`lingshu 找回 绿茶`。根据 AstrBot 的唤醒前缀配置，命令可能需要 `/` 或 @机器人。

## 配置与权限

`python` 留空使用 AstrBot 当前解释器。`timeout` 默认 15 秒；最多同时运行 2 个核心进程，最多接受 8 个待处理调用。`max_text` 默认 4000 字符，`reply_limit` 默认 1800 字符。`auto_recall` 默认关闭；开启后仅在 LLM 请求前按用户本轮消息召回，不自动改写人格。`recall_budget` 默认 1400 字符，包括说明文字，不是 1400 token。

`auto_capture` 默认关闭；开启后对话结束把用户本轮消息写回记忆库，只写用户消息、不写助手回答，敏感词（密码、密钥、token、银行卡号等）拦截，`capture_min_chars` 控制最小长度，`capture_interval` 控制同一用户的最小写回间隔。桥接只读取既有 `persona.json` 状态，绝不调用 `init` / `startup`，不创建、不注入、不改写宿主人格；启用自动写回前请先向用户告知隐私影响。

用户身份包含平台实例，例如 `aiocqhttp@qq_bot:10001`；以“身份”命令返回的值为准。旧版 `qq:10001` / `aiocqhttp:10001` 白名单不会自动生效。

管理员可以在本机执行以下命令添加主人，将占位值换成实际解释器、核心路径、数据目录与完整用户身份。所有路径必须属于运行 AstrBot 的同一个系统/容器。

```text
<Python解释器> <插件目录>/engine/scripts/brain.py --home <实际数据目录> channel owner add <身份命令返回的完整用户标识>
```

聊天中的“忘记”采用精确 owners 白名单检查，并向 CLI 传递调用者身份进行第二次鉴权。不要通过聊天提供任意 shell、扩展执行或完整 CLI 入口。

## 分享规则

“同意”允许当前平台实例内的其他群成员检索你在同一个群里写入的记忆；“拒绝”立即撤回后续检索授权，不会删除已保存的记忆，也无法撤回已经发出的消息。本人私聊可以找回自己的跨群记忆；群内找回只包含当前群的记忆。“我的信息”仅私聊可用。“问”必须提供对方完整身份与问题，按同群范围、目标用户和当前授权过滤。

## 数据与面板

本版不会自动读取或迁移 `~/.brain-memory` 的旧库。旧库可能已合并不同用户的相同文本，请先备份、审阅后迁移，不能仅改用户标识后当作隔离正确的数据库。

可选管理面板仍是独立本地全库管理界面。启动前给 `BRAIN_MEMORY_HOME` 设置与插件相同的数据目录；运行 `engine/scripts/panel_server.py --no-browser`，默认监听 `127.0.0.1:8765`。远程服务器可用 SSH 本地转发；Docker 需在容器网络命名空间内安排本地访问/隧道。单纯把容器端口映射出来无法访问只绑定容器回环地址的服务。不要直接改成 `0.0.0.0` 并公开端口。面板的扩展商店和自更新仍沿用上游逻辑，不属于本版验收范围，请勿用它覆盖修订核心。

## 验收与限制

先在测试实例验证两个不同用户、两个群、两个平台实例、授权/撤回和重启后的数据保留；可选自动召回还应验证具体模型提供商与其他记忆插件的交互。受限托管实例若禁止子进程或没有持久可写目录，本方案不可安装，需另做受保护的独立服务接口。

跨用户“做梦”与人格/情绪演化暂未开放。自动聊天写入需显式开启 `auto_capture`，且只写用户消息、不写助手输出。全库面板及本机 CLI 仍是可信管理员入口。标签化历史资料只能降低提示词注入风险，不能保证模型绝不会遵循恶意记忆；因此自动召回与自动写回均默认关闭。

此包不是上游官方发布，完整修订及待验证边界见 `PATCH_NOTES.md`。插件目录为可替换程序，记忆目录为持久数据；升级前备份数据，升级后重复验收。卸载或换回旧插件不会自动转换身份、撤销授权或删除本版数据。
