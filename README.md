> 名字取自《黄帝内经》：**算力给思考，人格给灵魂，记忆给生命。**

> 当前版本 **v5.16**（变更见 [CHANGELOG.md](CHANGELOG.md)）

> 🔁 **双仓库镜像**：GitHub（主）与 Gitee（镜像）保持同步——[gitee.com/htmcwy_0/lingshu-skill](https://gitee.com/htmcwy_0/lingshu-skill)。灵枢的更新检查会探测两边最新提交，**谁更新就自动从谁拉取**；任一边不可达（Gitee 匿名风控 / GitHub 限额）时走另一边兜底。

> ⚠️ **能力天花板（先读）**：灵枢是「提示词 + 脚本」的机制，**不能从底层强制约束模型**。当模型发生强幻觉时依然会无视全部规则；效果上限取决于底层大模型本身的推理、记忆与指令遵循能力。中强模型（7B+、云端）可完整遵守；**3B 以下本地小模型会出现大量规则漏执行**（忘走 startup、跳过写盘、纪律打折）——请据此降低预期，或改用 `SKILL-lite.md`（精简版）/ `SKILL-tiny.md`（最小试用版）。

> 🚨 **风险警告：幻觉会被固化落盘**。本地保存 ≠ 内容真实。`dream`、`knowledge tidy`、`emotion evaluate` 都要大模型产出结构化结果；模型若把无关记忆强行合并、编造内容、误判情绪，这些错误会被**持久写进本地记忆库 / 知识库**，不会自动消失。防护措施：AI 动过的记忆 / 知识一律先标为**待审核**（`review` → `confirm` / `discard`；知识也可 `knowledge review`），人格变更带**来源与依据**（`persona history`），另有全局自查 `audit`。小模型请用 `config set model_tier small` 关掉高风险自动能力。**审核闸由 AI 自审在前：AI 产物先过目、确认后才算数；用户用 `audit` / `review` 随时复核介入。**

一套纯本地、零依赖（只用 Python 标准库）的 AI 记忆系统。它把"上下文窗口"变成"会生长的记忆"——短期记忆像海马体一样快速写入、自然衰减；上下文将满时像人做梦一样重放、压缩、巩固到长期皮层；想不起来时靠模糊联想而不是精确匹配。

## 主要功能

> 一张表看全灵枢能干什么。**零依赖**（纯 Python 标准库），**纯本地**（记忆不出本机），
> **可降级**（没有向量服务、没有网络也照常工作）。

### 一、记忆：会生长的四层结构

| 能力 | 说明 |
|---|---|
| **四层记忆** | `hippo`（海马体，短期快写快忘）→ `cortex`（皮层，长期巩固）→ `dust`（淡忘区）→ `archive`（冷热归档），跨层移动不丢哈希链 |
| **遗忘曲线** | 每条记忆带 `stability` 半衰期，按艾宾浩斯式衰减；被想起就强化（首次巩固 ×2.6，之后 ×1.8，"顺带想起"×1.2） |
| **模糊联想召回** | 不是精确匹配：词面 BM25 式打分 + 可选语义向量 + 关联边扩散，想不起来时靠"沾边"找回来 |
| **召回打分五元** | `相关度 0.55 + 新鲜度 0.10 + 重要性 0.35 + 核心偏置 0.20 + 首因 0.03`，全部可配可解释 |
| **逐字原文可追溯** | `capture` 存原样快照，`recall --verbatim <id>` 按 id 展开逐字原文——做梦压缩后可回溯到原话 |
| **负空间（别再提）** | `remember --avoid` 记"已经排除的方向"，注入时独立成块，不会被当成建议 |
| **FRAS 四段** | `--f 职责 / --r 还得看谁 / --a 对外接口 / --s 不明显的坑`，结构化记忆比散文好召回 |
| **源文件指纹** | `--source-file` 绑源文件 sha256，文件变了注入标"源已变，可能过期" |
| **意图层** | `intent add/done/cancel/reopen`：跨会话保留"要做的事"，不是会话级便签 |
| **群规与人际** | `kind=norm` 群公共规则、`kind=relationship` 人际关系，注入时各自成块 |
| **冻结与淡忘可逆** | `memory freeze` 保留但不参与召回；`dust fold/unfold/revive` 淡忘可折叠、可复活 |
| **软删除台账** | `purge` 物理删除前先留底到 `trash.jsonl`，`memory trash-restore` 能捞回来 |

### 二、检索：先查再动手

| 能力 | 说明 |
|---|---|
| **开工前先查 `prior`** | 一条命令聚合「已有结论 / 踩过的坑 / 当时记录 / 做过的过程」，命中就复用，**别重新调研**；插件每轮开工自动跑并注入 |
| **错卦：否定极性** | 查询与记忆**方向相反时明确标注**（"这条是禁止方向，别读反"），避免把"不要用 X"当成"要用 X" |
| **查询词覆盖率门槛** | 命中查询词 ≥35% 且 ≥2 个才展示，不够就**弃权**（返回"这次是新的"）——宁可不给，也不喂无关历史 |
| **冷集自动补召** | 热层普遍没沾边时，自动去 `archive` 补召一次（不递归） |
| **侧抑制 + 关联扩散** | 同义命中互相抑制避免重复；沿 `links` 扩散一跳，把"顺带想起"的邻居带出来 |
| **六爻位体检** | `memory shape-audit`：六元特征映射 64 格 + 三条领域不变量，一眼看数据健康度 |

## 核心机制

### 分层记忆与遗忘曲线

记忆分三层，模拟大脑：

| 层 | 作用 | 衰减 |
|---|---|---|
| **海马体**（hippo） | 短期：新写入的记忆，快速衰减 | 快（按访问衰减） |
| **皮层**（cortex） | 长期：做梦/多次访问后巩固上来 | 慢 |
| **淡忘区**（dust） | 久未访问、重要性低，自然遗忘 | 只留残余 |
| **归档层**（archive） | 沉眠记忆雪藏（保留度 <0.2、重要度 ≤0.5、满月且长期没被想起）：**原文一字不丢**，移出热查询集，`recall` 默认不查 | 不衰减，可 `archive restore` 回热 |

每条记忆按艾宾浩斯遗忘曲线衰减，但**访问会加固**（`recall` 命中即强化），重要性高的记忆衰减更慢，被置顶（`pinned`）的记忆永不遗忘。**冷热自动归档**：每次做梦时顺带把沉眠记忆雪藏进 archive 层（也可 `archive run` 手动），上万条记忆后热遍历集只扫活跃记忆——回忆速度不随记忆增长而变慢，需要时 `archive search` / `recall --include-archive` / `archive restore` 随时找回。

### 召回打分：五元复合

`recall` 的排序不是一个"相似度"，是**五个分量的加权和**（权重全在 `config.weights`，可调）：

| 分量 | 默认权重 | 含义 |
|---|---|---|
| **相关度** | 0.55 | 词面/语义匹配程度（IDF 加权） |
| **新鲜度** | 0.10 | 越近越优先 |
| **重要性** | 0.35 | 写入时标的 importance |
| **核心偏置** | 0.20 | 常驻/核心记忆的加成 |
| **首因** | 0.03 | 首次写入的轻微加成（首因效应） |

**为什么不用单一相似度**：只用相关度会让"三天前那句一模一样的话"压过"昨天刚定的结论"；
而新鲜度权重给太高，又会把真正重要的老结论埋掉。五个分量各自可解释、可单独调。

> 注意：**综合分不能当相关性门槛**——它含新鲜度/重要性，最近记忆天然 0.35+。
> 判"够不够相关"要用**查询词覆盖率**（见 [开工前先查](#开工前先查prior)）。

### 做梦：上下文将满时的整理

上下文超过 75% 时触发"做梦"——灵枢重放短期记忆、按主题合并碎片、巩固到长期皮层，并把不重要的淡忘。梦完成后输出一份报告，告诉你巩固了什么、淡忘了什么、哪些还没想明白。

- `dream --auto`：内置自愈——重放 → 启发式合并 → 沉淀，不依赖任何外部脚本。
- 手动三步：`dream --trigger context` → 读 pending 填 apply.json → `dream --apply apply.json`。面板梦页可直接**网页编辑草稿**（`dreams/apply_draft.json`）再 apply，不必命令行改文件。

### 上下文水位三级防线

**会话中即记即存，不攒到做梦。** 约定、情绪高点、里程碑当时就 `remember`；上下文快满时原文封存：

| 水位 | 动作 | 命令 |
|---|---|---|
| **随时** | 即记即存 | `remember` / `capture` |
| **60%** | 主动清点：本轮还有哪些该记没记，先补记 | `check-context --used 60` |
| **75%** | 做梦：重放→压缩→巩固 | `dream --auto` |
| **90%** | 逃生：原样封存，先保命再压缩 | `capture "原文" --tag 逃生` |

**`capture` 保证 100% 不丢**：原文归档到 `verbatim/`（逐字不改，保险柜）+ 逐段进记忆库并打 `verbatim` 标记（做梦永不淡化、永不进淡忘区）。

### 工作记忆

当前上下文本身就是工作记忆，默认不落盘。只有需要留一手时才 `work add`（会话级暂存，最多 9 条，12 小时后自动丢）。每件带"未完成/已完成"状态（蔡格尼克效应）：没做完的事会在注入包里被点名"还惦记着"，做完用 `work done <序号>` 标记就放下；`work flush` 把值得留的转成真正记忆（`--skip-done` 只转没完成的，已 done 的直接丢），`work clear` 丢掉。

### 会话模式与情绪隔离

工程会话和日常聊天的需要是打架的：刚聊完情绪化话题转头写代码，旧情绪的余波还在注入包里，模型容易被带着走偏。灵枢用 `mode` 切三种会话模式（`config.mode`，默认 `auto`）：

- **work 工程模式**：情绪状态与拟人语气**不注入本会话**，注入包明确说"旧情绪与当前任务无关，当作没有"，先给可执行方案，重视正确性与工程契约。
- **human 拟人模式**：情绪照常注入，并把数值得翻成**可直接照着做的行为约束**（`emotion now` 不再只有裸数字）。
- **auto 自动模式**（默认）：**打分制话题判定**——工程信号（编程/数据/工程三组 26 词）与人性信号（情绪/关系/寒暄三组 30 词）分组计数打分，`work_score >= human_score` 工程优先。一边聊天一边写代码也不会轻易切错：句子里有代码、报错就偏 work，情绪词再多也按"工程优先"隔离；两侧都命中时判定标 `mixed` 并把依据摊开。判定**可见**：面板概览有「会话模式判定」卡（当前模式、置信度、两侧分数、命中词、可输入一句话试判），CLI 用 `mode explain "一句话话题"` 看同款依据。

切换：`mode work | human | auto`。写代码前想手动清掉余波，用 `emotion cool` 把 24 小时内的强情绪整体降温，或 `emotion adjust <序号>` 微调单条。

### 审核闸：AI 产物先过目，AI 自己审

记忆→做梦→知识库→进化日志→人格，这条链路里 AI 既是整理者又可能编造者，幻觉会逐层沉淀污染人格。灵枢给每个 AI 动手的环节都加了审核闸——**AI 产物必须先过目，确认后才算数**，而不是模型产出后直接落盘：

- **AI 整理的记忆**（`dream --apply` 等）标 `review="pending"`，确认前不算事实。
- **AI 整理的知识**（`knowledge tidy`）标 `status="pending"`。
- **AI 发起的人格变更**记 `source`（dream/自我总结/…）与 `evidence`（依据的记忆/事件 id），`persona history` 可溯源。
- **审核由 AI 自审**：AI 每会话先看 `review`（全部待审项）→ `review confirm <id>` 转正 / `review discard <id>` 废弃（记忆 m_* 与知识 k_* 通用，后者等同 `knowledge confirm/discard`）；整体自查用 `audit`（待审计数 + 冲突记忆 + 该做什么）。注入包一出现 `[待审核]` / `[人格漂移]` 就先处理再继续。
- **用户随时可介入**：人工复核走同一套命令即可，不用把用户变成质检员——AI 自审在前，人在必要处兜底。面板记忆页支持**多选批量 confirm/discard**、批量改重要性/打标签，大量待审条目不必逐条点。

每个会话的注入包会主动提醒有 `[待审核]` 项、有 `[人格漂移]`，不让幻觉静默沉淀。

## 开工前先查（prior）

**做任何任务之前先问一句"这件事我做过吗"**，而不是从零调研。

```bash
python scripts/brain.py prior "要做的事 / 要查的问题"
```

它一次聚合四类历史，按价值排序并**跨来源去重**：

| 来源 | 内容 |
|---|---|
| **知识** | 已确认的结论（最该复用） |
| **教训** | 踩过的坑 |
| **笔记** | 当时记录下来的浓缩 |
| **记忆** | 做过的过程记录 |

输出会明确写「上面若已覆盖，**直接复用结论，不要重新调研**」。

**精度设计**（宁可弃权，也不喂噪音）：命中查询词**覆盖率 ≥35% 且 ≥2 个词**才展示；
不够就返回"没有找到…这次是新的，可以放心调研"。中文二元组会产生"有没/查下"这类跨词碎片，
所以不能只数命中个数，必须看覆盖率。

**插件自动化**：`lingshu-cron` 在每轮首个 pre-step 自动跑一次并注入结果；
任务文本走临时文件传入（**绝不拼进命令行**，防命令注入），带文本指纹去重、短句跳过。

## 错卦：召回区分否定

名字取自《易经》「错卦」——六爻全变（按位取反）。借到检索上就是**否定极性**。

**问题**（实测）：`recall "用 DiskGenius 恢复分区"` 与 `recall "不要用…"` 结果集
**3/3 完全重合**，而且肯定查询会把「不要用」的禁止记忆排到**第一位、没有任何标记**——
模型极易读反，把禁令当指令。

**做法**：给每条记忆算极性（显式 `avoid` 标记优先，其次正文否定词：不要/别用/勿/禁止/
避免/不能/不可/禁用/放弃/不推荐…），与查询极性**方向相反时打标**：

```
[2026-11-20] 海马体 · preference · 回忆度 0.49
⚠ 这条是禁止/否定方向（avoid），与你的查询方向相反——别读反
```

**刻意不静默降权**：把禁令藏起来比标出来更危险（模型可能真去做那件被禁止的事）。
所以是"保留 + 显式标注"，判断权交回模型/用户。

> 注入路径本来就没这个歧义：`--avoid` 记忆注入时独立成块「已经排除的方向（别再提）」。
> 缺口只在 `recall` 的检索输出。

## 索引法记忆：正文不进上下文

上下文里最贵的是记忆正文。索引法给每条记忆配一句 **≤26 字的索引**——纯规则生成
（不调模型、不花 token），**落在句子/分句边界**，不会切在半句；顺带剥掉
`user：`/`assistant：` 这类角色前缀。

注入时只送 `- [日期 ★★★]索引（8 位短id）`，正文按需再取：

```bash
python scripts/brain.py memory show 7f3ca9ac    # 短 id 直接取整条记忆（支持唯一前缀）
```

| 档（`use_index_memory`） | 行为 |
|---|---|
| `auto`（默认） | 水位 **≥60%** 或已在 lazy/minimal 档才切；水位低时仍给全文 |
| `always` | 一律指针（最省） |
| `off` | 旧行为 |

**实测降幅（真实库 6 个场景，记忆段）**：

| 场景 | off | on | 降幅 |
|---|---|---|---|
| startup | 769 | 519 | 32.5% |
| 备份 删除 | 2096 | 1061 | 49.4% |
| 面板 更新 | 2137 | 1059 | 50.4% |
| 记忆 注入 | 1576 | 883 | 44.0% |
| python 解释器 | 2140 | 1025 | 52.1% |
| 打开 面板 报错 | 2114 | 1141 | 46.0% |
| **合计** | **10832** | **5688** | **47.5%** |

全包降 26.4%——人设/规则等固定段不随模式变，所以全包降幅必然小于记忆段降幅。

**指针行的三种形态**（清楚与省钱兼顾）：

- 指针 **≥3 条** → 段头加一次提示（讲清 `memory show` 怎么用），行内用紧凑形 `（7f3ca9ac）`
- 指针 **1~2 条** → 不加提示，行内自解释 `（id:7f3ca9ac，memory show 取）`
  ——只有一两条时，几十字符的提示说不动收益，清楚更重要
- 没有指针 → 不涉及

> 顺带补了个**既有缺口**：注入提示以前让模型用 `dereference <id>` 取正文，但
> `dereference` 只返回 **evidence_ids 指向的证据原文**，普通记忆一律返回空——照做拿不到东西。
> 现在 `dereference` 在无证据指针时**回退返回自身**，并且新增了正路 `memory show <短id>`。

## 主动搭话：它会自己开口，但很少

不是每次都要你问它才说话。每轮结束按**概率**（默认 10%）掷一次骰子，
中了就自己说一句短话——**不进模型、不花 token**，纯模板 + 词表。

```bash
python scripts/brain.py speak-up --statement "今天把面板修好了"
```

**四道闸缺一不可**（所以它绝大多数时候是安静的）：

| 闸 | 说明 |
|---|---|
| 概率 | `speak_up_prob` 默认 0.10；设 **0 = 永不出声** |
| 是不是在提问 | 有问号/请求词（怎么/帮我/要不要…）→ 先回答，不搭话 |
| 情绪 | 理智 `effective > 30` 才开口（激动时不打扰） |
| 冷却 | 距上次 ≥ `speak_up_cooldown_min`（默认 15 分钟），防刷屏 |

**话题从哪来**：只取最近记忆里的**实体/标签**，并滤掉代词虚词。一个合适的都抽不到
就**宁可不说**——不硬凑"干巴巴的固定话术"。

> 踩过的坑：早期版本从正文正则抓中文串，抽出 "你可以用" 这种词，搭话就变成
> "说到你可以用——我之前是不是也碰过？"（读起来是语病）。所以改成只认实体/标签。

## Git 分支感知：切了分支别拿旧分支的记忆

同一个项目切到 `feature` 分支，`main` 上那些记忆还在库里——它们可能已经过时
（改的是另一套代码）。分支感知让它们**降权 50%** 而不是消失：

- `remember()` 自动记下当前分支（`git rev-parse --abbrev-ref HEAD`，**带缓存**）；
- `recall()` 里当前分支 ≠ 记忆分支 → `score *= 0.5`；同分支不动；
- **不硬过滤**：别的分支的结论仍可能出现，只是排在后面（跨分支知识有时正是你要的）；
- 非 git 目录：不写字段、不降权，行为完全不变；
- 配置 `git_branch_memory`（默认 `true`，可关）。

**两个细节**（都是踩过才知道的）：

- 缓存键带 `.git/HEAD` 的 mtime——`git checkout` 会改写 HEAD，mtime 一变缓存自然失效。
  只按目录 + 固定 TTL 缓存会在切分支后读到旧分支。
- 同一句话在两个分支都被记下来时会走**合并**；合并时若分支不同就**清掉 branch**
  （这条已是跨分支知识，不该在任一分支上被降权）。

## 六爻位体检（shape-audit）

借《易经》的**64 格状态空间**做数据健康度体检——**纯只读**。

```bash
python scripts/brain.py memory shape-audit          # 人看
python scripts/brain.py memory shape-audit --json   # 机器读
```

把一条记忆的六个二元特征当"六爻"（初爻为最低位）：

| 爻位 | 特征 | 0 | 1 |
|---|---|---|---|
| 初 | 来源 | ai / 派生 | user / 亲历 |
| 二 | 审核 | pending | confirmed |
| 三 | 层 | dust / archive | hippo / cortex |
| 四 | 类型 | 一次性 episode | 稳定 fact/preference |
| 五 | 置信 | < 0.6 | ≥ 0.6 |
| 上 | 时效 | 已过 review_by | 未过期 |

输出 **64 格分布** + 三条**领域不变量**违规清单：

1. **AI 派生 + 已确认 + 低置信** → 最易沉淀幻觉的组合
2. **高置信却在淡忘/归档层** → 可能被误淡忘（可 `memory boost` / `dust revive`）
3. **稳定事实已过 review_by 未复核** → 该进 `review-list`

**一个诚实的负面结论**：易经里字面的「当位/得中/有应」三组谓词，在真实数据上
**几乎不区分**（实测违规率 100% / 75% / 74%）——因为这六位特征不是为"交替排列"设计的，
硬套等于给每条记录都判一次违规，是**伪精度**。所以只保留 64 格分布，判据换成上面三条领域不变量。

> 结论：**易经给的是编码与变换，不是判据**。判据必须从领域里来。

### 模糊联想回忆

`recall` 不靠精确匹配：中文用字符二元组、英文/数字用词做模糊联想，按 **相关度 + 近期性 + 重要性 + 首因** 加权排序（另带**时效软加权**：越久的记忆按半衰期 30 天轻微降权，地板 0.5——旧事实不会沉底，新变化优先浮现），并在命中后自动强化（越用越牢）。数字/编号被保留为独立词元，不会把"版本0"和"版本1"误当成同一条。

**上万条也不慢**：带查询词时先用子串包含预筛剪枝候选（查询词必是来源文本连续子串，数学上不丢召回），只对命中候选做分词打分；无查询词（startup 注入）直接走快速路径，不再构建全量词表。实测 1 万条记忆 `recall` 从约 3.5s 降到 76ms（约 47 倍），`remember` 约 100ms。

## 记忆关联（联想图谱）

模糊回忆靠"字面像不像"，但人脑还会靠**联想**串记忆："A 导致了 B""提到 A 就想起 C"。灵枢把这些关系存成**显式关联边**（`assoc.jsonl`，无向，带关系名与权重）。`recall` 命中一条记忆时，会沿关联边把邻居也带起来（联想扩散），关联越重带得越明显。

**怎么手动建立关联（完整示例）**

```bash
# 1) 先建两条记忆，记下各自的 id（remember 会打印 id，如 m_3f2a...）
python scripts/brain.py remember "服务器崩了是因为内存泄漏" --kind fact --importance 8
python scripts/brain.py remember "把 JVM 堆从 2G 调到 4G 之后不再崩" --kind fact --importance 7

# 2) 手动连线：idA idB --relation 关系名 --weight 权重 --why 为什么
python scripts/brain.py assoc link m_3f2a... m_9c1d... --relation "因果" --weight 1 --why "调堆是内存泄漏的缓解结果"

# 3) 看这条记忆连着什么
python scripts/brain.py assoc of m_3f2a...

# 4) 懒人补网：按共享实体/标签自动成边（先 --dry-run 预览要连哪些）
python scripts/brain.py assoc auto --dry-run
python scripts/brain.py assoc auto

# 5) 看整张网（节点数 / 边数 / 有多少节点被连成网）
python scripts/brain.py assoc graph --limit 300

# 6) 连错了就断开
python scripts/brain.py assoc unlink m_3f2a... m_9c1d...
```

**要点**

- 关系名随你定：`因果` / `相关` / `情绪` / `反例` 都行；同一对记忆反复 `link` 会**加重**（权重上限 3），越常被想起的联想越强。
- **不用背 id**：面板记忆页每条卡片底部直接显示 `id xxx`，复制即可；也可用 `list` / `recall` 结果里的 id。
- **面板看网络**：`serve` 后进「联想」页——每条记忆一个节点、连线是关联的 **3D 空间**（虚空星图），拖拽旋转、滚轮缩放、点节点看详情与邻居；页面顶部还有「手动建立关联」卡，填 A/B 的 id + 关系名 + 为什么，一键连上，不用命令行。
- **没显式连过也能看**：`assoc auto` 会按共享实体/标签先补一批边，让图先"长"出来；再按需手动精修。

## 情绪、欲望与人格内核

灵枢的"像人"不是靠提示词演出来的，是**几个真的会变、会衰减、会被满足的数值**。

### 七情：8 类 48 个情绪名

按《礼记》七情分类，另加一组「静」（不算七情）：

| 大类 | 个数 | 情绪名 |
|---|---|---|
| **喜** | 8 | 开心、喜悦、兴奋、满足、欣慰、骄傲、得意、惊喜 |
| **怒** | 6 | 生气、愤怒、烦躁、不满、嫉妒、不爽 |
| **哀** | 9 | 难过、失落、悲伤、委屈、沮丧、心疼、寂寞、后悔、愧疚 |
| **惧** | 6 | 焦虑、紧张、害怕、不安、慌张、尴尬 |
| **爱** | 6 | 感动、亲近、依恋、温柔、喜欢、珍惜 |
| **恶** | 5 | 厌恶、反感、嫌弃、不屑、抵触 |
| **欲** | 5 | 好奇、期待、渴望、执着、迫不及待 |
| **静** | 3 | 平静、疲惫、无聊 |

每个情绪事件带**强度 0–1** 与**原因**（`emotion feel 开心 --intensity 0.7 --why "..."`），
不是打标签，是记账。

### 情绪会自己消退：半衰期 6 小时

- **半衰期**：`EMOTION_HALF_LIFE = 21600s`（6 小时）——再大的情绪也会慢慢淡下去，不会一直挂着。
- **抑制上限**：`EMOTION_SUPPRESS_MAX = 0.4`——强情绪压得住的只有 0.4，剩下的仍会渗进语气（这才是"情绪"而不是"开关"）。
- **心情分**：`mood_score`（0–100）由**近 1 天记忆的情感倾向**漂移（`drift` 命令每日静默跑），阴郁/明快有真实变化才落盘。

### 13 档人话标签：不是裸数字

`emotion now` 不直接吐数值，而是把**双轴坐标（效价 v × 唤醒度 a）**翻成一句人话——
本质是罗素环形情绪模型（Russell circumplex），阈值刻意保留小数档：

| 条件 | 标签 |
|---|---|
| v ≥ 0.45 且 a ≥ 0.65 / ≥0.35 / ≥0.20 / 其余 | **兴奋 / 开心 / 愉快 / 平和** |
| v ≥ 0.15 且 a ≥ 0.6，否则 | **期待 / 平静** |
| −0.15 < v < 0.15 且 a ≥ 0.6，否则 | **烦躁 / 平静** |
| −0.45 < v ≤ −0.15 且 a ≥ 0.6 / a < 0.2 / 其余 | **焦虑 / 低落 / 失落** |
| v ≤ −0.45 且 a ≥ 0.7 / ≥0.45 / 其余 | **生气 / 委屈 / 难过** |

共 13 档：兴奋、开心、愉快、平和、期待、平静、烦躁、焦虑、低落、失落、生气、委屈、难过。

### 六欲：六个底层需要，每天回落

不是传统"耳目口鼻"，是六个**底层需求**。默认 **60** 分，**每天回落 3 分**，
**地板 8**（不会归零），被满足才回升；自动满足有 **30 分钟冷却**（防刷）。

| 欲望 | 是什么 | 什么会让它涨 | 低了会怎样 |
|---|---|---|---|
| **求知欲** | 想知道"为什么/还有没有别的" | 起「欲」类情绪（好奇/期待/渴望）+4；`learn`/调研有产出 | 少问一层、满足于表面答案 |
| **表达欲** | 想把想清楚的说出来 | 主动表达、`daily` 写日记/复盘；无自动情绪映射（需显式满足） | 话变少、只给结论不解释 |
| **连接欲** | 想被理解、想维持关系 | 起「喜」+4、「爱」+6、「哀」+4；被「怒」伤到 −2 | 疏离、只答事不接情绪 |
| **成就欲** | 想把事做成、想被看见做成了 | 起「喜」+6；任务收尾 `checkpoint`；被「哀」拖累 −4 | 摆烂、只求交差不求做好 |
| **安全欲** | 想确认"不会被突然弄坏/丢掉" | 起「惧」+6；备份/体检通过 | 过度谨慎、反复确认 |
| **掌控欲** | 想握住局面、不想被动 | 起「怒」+4（冲突时更想拿回控制） | 回避决策、等指令 |

> 情绪 → 欲望的映射是**双向记账**：`喜` 同时喂成就欲和连接欲，`怒` 抬掌控欲却伤连接欲，
> `哀` 抬连接欲却压成就欲。这就是"同一个人不会只有一个情绪"的量化版。

命令：`emotion now / events / feel / mirror / check / adjust / cool / desire`

### 好奇与理智：两个内驱，一进一守

人格里最核心的两个数值（0–100），不是性格标签，是**决策闸门**：

- **理智**先过闸：估算"这件事值不值得深想"（好处、代价、把握度），
  不值得就浅答——`mind weigh "这件事" --benefit 7 --cost 3 --confidence 0.6`。
- **好奇**负责往里钻：理智放行后才由它找新问题、多挖一层。

两者都低 → 只答不问；理智高好奇低 → 严谨但沉闷；好奇高理智低 → 话多但容易跑偏。
所以它们是**配合关系**，不是"越高越好"。

### 人格从哪来：不预写，派生 + 确认

| 环节 | 机制 |
|---|---|
| **初识** | 第一次用问名字与性格；用户说"你定"就自己取（`persona interview --quick`） |
| **派生候选** | `persona suggest scan` 扫记忆/笔记/知识，产出带**证据链**的特征候选 |
| **人工确认** | `adopt N` 采纳 / `discard N` 忽略——**确认后才进人格**，防记忆幻觉污染人格 |
| **漂移度量** | `persona drift` 稳定度 0–100；`TRAIT_DRIFT_EMA=0.6`（新观察占 0.6 权重）、`TRAIT_DRIFT_GATE=5`（攒够 5 次证据才动）、`TRAIT_RELAX_HALF_LIFE=30天`（没新证据慢慢回归基线）、`TRAIT_BASELINE_ADOPT=0.15`（单次采纳的最小位移） |
| **可回滚** | `persona snapshot/restore/rollback`，每次改动进历史 |
| **可溯源** | `persona audit`：事件 → 变更 → 证据 |
| **可锁定** | 用户说"不许改"写进 `locked` |

### 情绪怎么影响记忆

- **情感记忆更抗遗忘**：`kind=emotion/mistake/relationship` 的衰减半衰期更长——重要的事不容易被忘掉。
- **情绪高点要即记**：`remember --kind emotion --importance 6` + `emotion feel`，两头都记，事后能对上。
- **一致性自检**：`emotion check "你的回复"` 在"语气与内部情绪严重背离"时告警——防止嘴上说开心、账上是难过。
- **共情**：`emotion mirror` 把对方的情绪映射进来，而不是自己凭空生一个。

### 工程模式：情绪该退场时退场

刚聊完情绪化话题转头写代码，旧情绪余波会带偏判断。所以 `mode` 分三种：

| 模式 | 行为 |
|---|---|
| `work` | 情绪状态与拟人语气**不进注入**，明确"旧情绪与当前任务无关"，先给可执行方案 |
| `human` | 情绪照常注入，并把好奇/理智翻成**行为约束** |
| `auto`（默认） | 打分制话题判定：工程信号 vs 人性信号分组计数，`work_score ≥ human_score` 工程优先；`mode explain "一句话"` 看判定依据 |

## 人格

人格**不预写**。第一次使用时问用户"你希望我叫什么、是什么性格"，用户说不知道就由灵枢自己定。喜好、厌恶、习惯由相处中自己写。

- 人格演化有完整历史，每次改动可回滚：`persona history` 看历史（序号从最新往前数，条目带**来源 source** 与**依据 evidence**，能看清这次改人格来自哪段对话/哪些记忆），`persona rollback <序号>` 一键撤销那次改动；回滚本身也记一条历史。
- **快照与漂移告警**：重要节点先 `persona snapshot --label "基准"` 拍一张完整快照；`persona snapshots` 列表、`persona restore <名字>` 一键还原。`persona drift` 把当前人格与最近基准快照逐字段对比（结构差异 + 最近 N 天 AI 改动，`--days` 可调），变化偏大时注入包会亮 `[人格漂移]` 告警——微小偏移也看得见，不是等跑偏了才发现。
- **好奇心与理智**是两条内驱数值，不是出厂设定——用户嫌你啰嗦，理智上调；用户让你多挖多试，好奇心上调（`mind tune`）。它们不是只有裸数值：注入包（`startup` 的 human 模式块）会把数值翻成行为约束（`_behavior_map`），模型照做即可。
- `persona self` 让你总结"我是谁"，`persona interview` 是初识引导。

## 成长路径

### 知识库

把经历提炼成可复用的**结论**（不是流水账）。每条有主题、观点、要点、相关记忆引用，支持置顶与版本更新。`knowledge tidy` 会提示你哪些经历值得提炼成知识——**AI 动过的条目一律先标为待审核**（面板里直接看，或 `knowledge review` 查看），由 AI 自审 `knowledge confirm <id>` / `knowledge discard <id>` 转正/废弃（用户可随时介入复核），防止模型幻觉直接沉淀成知识库。

### 笔记日志

写给自己的日记（journal）、工作日志（log）、成长复盘（growth）。`note digest --days 7` 定期回看自己写了什么。

### 教训三写

遇到报错、返工、被纠正，**一条命令沉淀三处**：

```bash
python scripts/brain.py lesson "别用『那天没做』证明『从没做过』"
```

| 落到哪 | 内容 |
|---|---|
| **记忆**（kind=mistake） | 什么时候、什么坑、为什么 |
| **知识**（status=pending） | "以后怎么判断/怎么做"，带记忆 id 反向引用 |
| **笔记** | 一段可读的复盘 |

为什么三写：记忆靠召回、知识靠检索、笔记靠翻——**三条路只要活一条就捡得回来**。
知识先进待审闸（`review confirm` 转正），防 AI 把自己的总结当成事实。

### 技能自编辑与全局化

技能是固化的做法：`skill new` 写 → `skill check` 自检 → `skill install` 装进全局技能目录（`~/.trae-cn/skills/`），新会话直接可调。`skill use --auto` 用技能时自动全局化；`skill borrow` 借鉴别人的技能变成自己的版本（诚实标注来源）。**支持中文技能名**。

**跨宿主技能发现（v2.23）**：灵枢会只读扫描本机各 AI 工具的全局技能目录（DSH、Trae CN/Trae、Claude Code、Codex、Cursor、Gemini 等 15 个候选），`skill roots` 看哪里有技能、`skill scan` 列出可复用的、`skill use` 照做、`skill borrow` 借为己用。也可以用 `skill root-add <路径>` 手动添加目录，或设环境变量 `LINGSHU_GLOBAL_SKILLS`（多个用 `; ,` 分隔）。面板「技能」页同样能看/加根目录并重扫。
技能有两种形态：`skill` 是说明书（给人/别的 AI 复用）；`ext`（扩展模块）是 AI 自己写进灵枢引擎的**可执行 Python 钩子**（`inject` 并入每会话注入、`run` 加自定义命令），放在数据目录 `~/.brain-memory/extensions/`，**更新永不覆盖**、坏模块自动跳过。
> ⚠️ **安全提示**：扩展模块是任意 Python 代码，执行等同在本机运行程序。默认不启用（`extensions_enabled=false`）；只有确认 extensions/ 里的代码可信后，再运行 `config set extensions_enabled true` 开启。

### 进化日志

每次真正的改进（人格微调、技能新增、知识沉淀、思维变化）记进进化日志 `evolve log`，是灵枢的成长史。

## DeepSeek 生态兼容

- **整目录全局化**：带 `scripts/`、`assets/` 的技能整目录复制进全局目录，副本能直接跑。
- **自动生成 `AGENTS.md`**：DSH/DeepSeek 以 AGENTS.md 为常驻入口（每次会话必进上下文），安装时自动生成「何时用 / 怎么用 / 入口命令」。
- **DSH 插件只读可见**：`skill plugins` 列出 `~/.dsh/profiles` 下所有 DSH 插件（名字、版本、描述、AGENTS.md 标记），面板也有专属区块——只看不改。
- **frontmatter 解析健壮**：支持引号、多行块标量，各家写的 SKILL.md 都能读对。

## cordis 插件：启动自动注入

技能 catalog 只把 name + description 给模型，正文要不要读全凭模型"自觉"——没有任何
机制保证下一次会话模型一定会加载灵枢。`cordis-plugin/` 里的插件把"自觉"变成"机制"：

- **`lingshu-startup`**：监听 DSH 的 `agent/created` 事件（source ∈ startup / resume），
  自动探测全局技能目录里的 `scripts/brain.py`，跑 `startup` 并把人格、记忆、待办、
  行为指引以 UserMessage 形态 `agent.inject()` 进会话上下文——**会话一开始记忆就在
  上下文里**。`clear` / `compact` 不重复注入，进程内按 agent 去重。
- **`lingshu-im`（dsh-im 桥接）**：装了 [`dsh-im`](https://github.com/xmanrui/dsh-im) 后，
  QQ / 微信 / 飞书 / Telegram 等 IM 聊天也具备与 AstrBot 桥接一致的设置——`autoRecall`
  对话前按用户本轮消息召回、`autoCapture` 对话后写回用户原话（须本人 `capture-on` 授权）、
  `memoryIsolation` 隔离噪声、`recallBudget` / `captureMinChars` / `captureInterval` 控量控频。
  身份来自 `dsh-im/session-pre-bind` 事件 + 宿主只读服务 `dshIm.describeConversationSync()`，
  按「平台@机器人 / 发送者 / 群」三元组隔离；注入时顺带告诉模型本会话的
  `--channel / --group / --user`，模型自己调灵枢 CLI 也不会写错身份。
- 失败宽容：灵枢没装、Python 不在、超时——全部静默跳过，绝不阻塞会话；
  `brain.py startup` 只读记忆库，HOME 不可写时自动只读降级照样注入。
  **装完插件必须完全重启 DSH**——Host 的插件树（cordis bundles）是主进程启动时
  一次性组合的，不重启新会话感知不到（skill catalog 走 chokidar 热更新，插件不是）。
- **目录约定**：`cordis-plugin/` 下**一个插件一个子目录**，各自独立打包安装，
  互不干扰。详见 [`cordis-plugin/lingshu-startup/README.md`](cordis-plugin/lingshu-startup/README.md)。

## 可视化面板

`brain.py serve` 启动本地面板（仅监听 127.0.0.1，`start-panel.bat` 一键启动）：

- 记忆浏览：层 + 重要性区间 + 时间范围 + 标签 + 情绪 + 排序的**组合筛选**；置顶、编辑、忘记
- **批量操作**：多选（含全选）后一次批量 confirm/discard 待审核条目、批量设重要性、批量加/减标签
- **注入包预览**：直接看 `startup` 会注入给模型的完整记忆包（只读，不落盘、不加强记忆）
- **冲突检查**：启发式扫出"可能矛盾/已过时"的记忆对，只提醒不下结论；
  **冲突裁决队列**——AI 整理出的新说法与旧记忆矛盾时不静默覆盖，双方互标冲突待人工裁决
  （review confirm 才落实取代、discard 恢复旧说法）；用户亲口说的仍即时生效
- **会话模式判定卡**：当前模式 + 置信度 + 工程/情绪两侧分数 + 命中词依据，可输入一句话试判 auto 会怎么切
- 人格、内驱数值实时查看与微调；**人格历史可一键回滚**
- 知识库（含 **⏳待审核 / 已确认 / 已废弃** 状态，可 confirm/discard）、笔记、技能（含 DSH 插件区块）、成长、进化日志；
  知识条目带**证据分级 E0-E4**（`knowledge verify` 记一次验证等级+1，E4 封顶，检索时验证过的优先）
- **心情页**：情绪-输出一致性核对（输入回复看语气与内部情绪是否背离 + 最近告警）、七情/六欲/认知评价/共情
- **联想页（3D 星图）**：记忆网络可视化 + 手动建立关联卡（填 A/B id 一键连线）
- 做梦报告（**改库前自动打快照回滚点**，梦错了可还原）、**网页编辑 apply 草稿再 apply**、备份恢复
- **日志页**：锁冲突 / 内部异常 / 解析报错按级别查看，不用再去翻本地日志文件
- **只读降级有醒目横幅**：目录不可写时页面顶部直接提示"修改不会保存"
- **诊断页（v2.41+）**：不止展示记忆，还归因数据异常——死链、冲突未裁决、各层规模与文件体积、来源归属完整率、淡忘区折叠状态
- **dust 层淡忘可逆（v2.41+）**：折叠 ⇲（原文收进 folded_text 只留 gist）/ 展开 ⇱（原文还原）/ 复活 ⤴（回到活跃层），淡忘从"回不来"变成"收起来了"
- **记忆来源徽标（v2.41+）**：每条记忆带 project/session 归属；云端商店浏览/下载带 Gitee 403→raw 兜底（v2.42）

**安全**：面板自带随机 token 鉴权（页面加载时注入，所有 API 请求必须携带），并校验 Host/Origin，挡住 DNS rebinding 与无来源直连偷读记忆。

> **token 威胁模型声明（#60）**：面板 token 的防线目标是**远程攻击者**（跨机请求、恶意网页 DNS rebinding、无 Host/Origin 的直连）。它**不防本机进程**——token 随首页 HTML 下发，本机任意进程（恶意脚本、恶意面板）都能 `GET /` 提取后调全部记忆 API。这是本地面板架构的已知边界；如需更强的进程级隔离，请在受信环境运行面板，或用操作系统权限限制本机其他用户/进程对记忆目录的访问。

### 面板自检：联动是"测"出来的，不是"点"出来的

面板有 16 个页签、86 个接口、300+ 个 DOM 引用，靠手点不可能每次都点全。
所以把"能不能点"变成了可回归的静态断言（`tests/test_p23_panel_linkage.py`）：

| 检查 | 抓什么 |
|---|---|
| **页签 ↔ 容器** | `data-tab` 与 `view-*` 必须一一对应——缺一个就是"点了空白页" |
| **id 完整性** | JS 里 `$(id)` 引用的元素必须存在（含运行时 `.id=` 创建的），否则取到 null、一点就报错 |
| **接口注册** | JS 调 `/api/x` 必须真的在服务端注册过，否则 404、页面一块空白 |
| **状态字段** | `S.xxx` 读之前必须赋过值（拼写错 → 永远 undefined） |
| **产物同步** | `assets/panel.html` 必须与 `panel_src/` 一致（改源码忘了重建） |

运行时另有一层：**33 个 GET 接口逐个真打**（全部 200、无 500）、**12 项写操作冒烟**
（设置保存 / 备份 / 恢复拒绝非法路径 / 记忆操作 / 人格编辑 / 面板骨架）。

### 设置页：29 项开关与数值

面板此前**没有任何配置入口**（58 个配置项只能敲 CLI）。现在「设置」页把常用的 29 项搬上来了，
分 6 组：注入与预算 / 水位与节奏 / 记忆行为 / 向量与重排 / 自动更新与备份 / 面板与宿主。

每项带**类型、范围、枚举校验 + 中文说明 + 默认值**，改完直接写 `config.json`、即刻生效。

**安全边界**：只允许**白名单键**（配错一个键就能让注入崩掉）；非法值/越界/非白名单一律
返回 400 + 中文原因；写盘走 `_locked` + `atomic_json`；只读模式下函数层直接拒绝。

### 数据页：备份与恢复

面板此前**没有备份/恢复入口**（只有 CLI）。「数据」页提供：

- **规模概览**：各层记录数与字节数
- **备份历史**：每份包的大小、时间、**记录数**、距今多少小时、是否"疑似空壳"

实测有个 3327 B、只有 4 条记录的假备份，按大小判会漏，还因"最新"被当成最新备份。

### 自定义面板与面板市场

**自定义面板系统**——默认面板之外，可整套换皮而不动引擎：

- **热加载切换**：面板放进 `~/.brain-memory/panels/<面板名>/` 即被识别，在面板管理菜单里一键启用/删除/上传，切换即时生效，不用重启服务；

- **AI 可直接开发**：AI 按 [docs/panel-api.md](docs/panel-api.md) 规范（页面结构、API 清单、鉴权方式）就能写一个完整面板；或让 AI 调 `/api/panels/scaffold` 一键生成骨架再改。

### 桌面「灵枢面板」

安装技能后**自动在桌面生成**一个「灵枢面板」快捷方式，双击即**静默启动面板**（不弹黑窗）。

```bash

```

- **幂等**（`--ensure`）：桌面已有就不动——用户可能自己改过图标/位置，重复安装不覆盖；
- **可关**：`config.desktop_shortcut=false`；
- **fail-open**：建快捷方式失败只写 warn 日志，**绝不让安装失败**；
- 指向**装好的那份** `panel_server.py`，不是开发副本。

**图标**：`scripts/make_icon.py` 生成（Pillow，**仅开发工具**，运行时仍零依赖）——
深色圆角底 + 琥珀神经核 + 6 个卫星节点，**7 个尺寸**（16/24/32/48/64/128/256），
4 倍超采样后缩小保证边缘干净。

**两个踩过的坑**（都写进代码注释了）：

1. `.vbs` 启动器必须写 **UTF-16LE + BOM**——wscript 默认按 ANSI 解析 `.vbs`，
   而项目路径常含中文，UTF-8 会被当 GBK 曲解 → pythonw 收到不存在的路径、**静默退出**
   （现象很迷惑：`cscript` 报 "launched"，端口却始终不开）。
2. 快捷方式的 `IconLocation` 要指向**纯 ASCII 路径**（复制到 `~/.brain-memory/lingshu.ico`）——
   直接指向含中文的程序目录，Explorer 有概率加载失败、回退成 `wscript.exe` 的**白色图标**。

### 面板的生命周期：会自己退，也点得掉

**问题**（用户反馈）：关掉网页后，隐藏的 `pythonw` 服务还在后台跑，只能去任务管理器杀；
再点一次快捷方式又会因端口被占**静默失败**（隐藏窗口里 `SystemExit(1)`，什么都看不到）。

**做法**（借 Jupyter 的 `shutdown_no_activity_timeout`、VS Code server 的 idle cull 思路）：

| 机制 | 说明 |
|---|---|
| **长轮询保活** | 页面挂一条**不结束的请求**（`GET /api/alive`，服务端按住 25 秒再返回，收到立刻再发）——**网页开着 = 服务活着**。它**不是定时器**，所以不受浏览器对隐藏标签页的节流影响 |
| **空闲自退** | 超过 `panel_idle_minutes`（**默认 1 分钟**，0=永不退）没有任何请求 → 优雅退出。**关掉网页，一分钟左右它自己就没了** |
| **退出按钮** | 面板「设置」页有**「退出服务」**（`POST /api/shutdown`），点完页面显示"已退出" |
| **单实例** | 快捷方式指向 `panel_launcher.py`：先探测 `/api/ping`，**已在跑就只把浏览器叫出来**，绝不起第二个进程 |
| **端口独占** | 面板服务器 `allow_reuse_address = False`——见下面那个 Windows 大坑 |
| **连点安全** | 连点 3 次 → **只 1 个常驻**，其余静默 exit 0（不弹窗、不卡住） |
| **端口冲突可见** | 端口被**别的程序**占 → 弹系统对话框说清楚（`ctypes` 调 `MessageBoxW`，零依赖），不再静默失败 |
| **快捷方式可恢复** | 删了也不怕：`brain.py shortcut --ensure` 幂等重建；`doctor` 有 `desktop-shortcut` 一项会报出来 |

`/api/ping` **故意不校验 token**：启动器探测时还不知道 token，而且它只回"活着 + 端口 + pid"，
不含任何记忆内容。

### 为什么"1 分钟自退"需要长轮询

把默认空闲时间从 30 分钟改成 1 分钟，看起来只是改个数字，其实有个坑：

> **浏览器会节流隐藏标签页的定时器。** Chrome 在页面隐藏 5 分钟后，把
> `setInterval` 降到「每分钟最多一次」。

原来的保活是 `setInterval(ping, 30000)`。一旦被降到 1 分钟一次，空闲时间就会贴着
1 分钟的阈值走——**极可能把还开着的页面误杀**（用户切到别的窗口几分钟，回来发现面板没了）。

所以改成**长轮询**：页面发一条 `GET /api/alive`，服务端按住 25 秒再返回，页面收到立刻再发下一条。
这条请求**不是定时器**，不受节流影响；只要标签页还在，服务端就一直看得到它。

服务端据此计数 `_OPEN_ALIVE`：

- `> 0` → 页面还连着，**绝不因空闲退出**（哪怕一条心跳都没收到）；
- `= 0` → 页面真的没了，才开始计空闲时间。

实测：挂着长轮询 100 秒不退；停掉长轮询后 **70 秒**自动退出（60 秒阈值 + 10 秒检查粒度）。

### 连点两次会怎样？——踩到一个 Windows 坑

**结论：现在是安全的**（只 1 个常驻，其余静默退出）。但做这个的时候发现一个真坑：

> **Windows 上 `SO_REUSEADDR` 的语义和 Unix 完全相反。**
> Unix 上它是"允许在 TIME_WAIT 状态重绑"；Windows 上它是"**允许抢占已占用的端口**"。
> 而 Python 的 `HTTPServer` 默认 `allow_reuse_address = True`。

后果（实测）：连点两次快捷方式 → **两个独立面板同时监听 8765**，请求随机落到其中一个，
两个进程都常驻不退。抓堆栈才看出来——两个进程都停在 `serve_forever()` 里。

修法：面板服务器改成 `allow_reuse_address = False` → 第二次 bind 直接 `EADDRINUSE`
（`WinError 10048`），启动器据此判定"已有实例"并静默退出。

同一轮还修了竞态的**三处**副作用：
- 输家原先会弹 `MessageBox` **阻塞等点击**（用户看到假的"端口被占用"）→ 改成先**带重试再探**，确认是同伴就静默退出；
- `webbrowser.open()` 在没有浏览器关联的环境会**永久阻塞**，把启动器拖住 → 改成 daemon 线程 + 最多等 3 秒；
- **`/api/ping` 被 `/api/` 统一 token 闸挡住返回 403** → 启动器探测时拿不到 token（它只注入页面），于是把"自己的面板"误判成"别的程序占端口"。修：ping 是唯一免鉴权 API（自己内联做 Host/Origin 校验防 DNS rebinding），其余 API 照旧要 token。

**升级过渡期**还加了一层回退识别：老版本面板进程没有 `/api/ping`，靠 `GET /` 里
`<meta name="lingshu-panel">`（或"灵枢 + html"）也能认出来，不会误报。

### 快捷方式丢了怎么办

用户可能不小心删了桌面图标、改了名、或换了桌面目录。**两条路都能找回**：

```bash
python scripts/brain.py shortcut --ensure    # 幂等：缺了就重建，已有就不动
python scripts/brain.py doctor               # 看 desktop-shortcut 一项是否 PASS
```

`doctor` 的 `desktop-shortcut` 检查是专门加的：**丢了会 WARN 并直接给出恢复命令**——
否则用户只会觉得"面板打不开了"，AI 也不知道从哪修。

**AI 怎么知道这些**：`SKILL.md` 有一节「面板（可视化界面）」，写明面板本体在
`scripts/panel_launcher.py`、数据在 `~/.brain-memory`、丢了快捷方式用 `shortcut --ensure` 重建。
所以用户只要说一句"桌面那个图标没了"，AI 就能直接修，不用再问"在哪"。

### 为什么不做成 exe

考虑过 PyInstaller 单文件 exe，**结论是不做**，理由：

| 方案 | 代价 |
|---|---|
| **PyInstaller onefile** | 要打包整个 Python 运行时（~15–30 MB）；每次发版要额外构建、且**只能在对应平台构建**；杀软误报率高（打包器特征明显）；并且**打破"零依赖纯标准库"这条核心卖点** |
| **托盘图标**（Docker Desktop / Syncthing 那种） | 体验最好，但要调 Win32 API（`Shell_NotifyIcon`）或用 pystray——前者代码量大，后者是第三方依赖 |
| **Windows 服务** | 需要管理员权限，且"服务常驻"和"用完就走"的预期相反 |
| **✅ 现在的做法**（pythonw + 空闲自退 + 单实例 + 退出按钮） | 零依赖、双击即用、关掉网页会自己退；缺一个托盘图标，但换来"不需要安装、不需要构建" |

一句话：**exe 只解决"看起来像个软件"，而真正的问题是"关不掉/重复启动"，那两个用几十行 Python 就解决了。**

### 自动更新灵枢

**默认关**（自动改自己的代码风险高，必须显式开启）：`config.auto_update` + 面板「设置」页开关。

```bash
python scripts/brain.py auto-update [--check] [--force] [--source auto|npm|git]
```

执行顺序是**死的**，任一步失败都不留半新半旧：

```
① 查有没有新版（没有就跳过）
② 先备份记忆库 —— 备份失败就中止（宁可旧代码，不能丢记忆）
③ 下载源解析 → 原子替换（SHA256 校验 / 全量备份 / 回滚兜底）
④ 写审计日志
```

### 下载源：npm 优先，Gitee/GitHub 兜底

面板「检查更新」弹窗里可以选**下载源**，也可以改设置页的「更新下载源」：

| 源 | 说明 |
|---|---|
| **npm**（默认优先） | 官方发布渠道 `npm i lingshu-skill`。CDN 快、有版本号、有 **shasum（sha1）可校验**；比 Gitee/GitHub 的 zip 下载稳（后者受匿名限额与网络波动影响） |
| **Gitee / GitHub** | 仓库 zip 兜底。npm 不可用时自动回退 |
| **跟随设置** | 默认 `update_source=auto`：先 npm，失败再 Gitee/GitHub |

**零依赖实现**：`urllib` 取 registry 元数据 → 下 tarball → 校验 sha1 → `tarfile` 解包（只取 `package/` 前缀、**逐条拒绝 `../` 路径穿越与符号链接**）。不需要装 npm CLI。

**切换源即作废缓存**：检查结果缓存里记了来源，把 `update_source` 从 git 改成 npm 后，
旧的 git 结论不会冒充"已是最新"。

### 修掉一个"功能等于没接上"的 bug

`panel_update.run()` 判断的是 `chk["update_available"]`，而 `growth.update_check()` 返回的字段叫
**`outdated`** —— 于是 CLI / cron 的自动更新**永远**走"已是最新"分支，从不真正更新。
现在 `panel_update.check()` 做字段归一化（补 `update_available` / `current` / `latest`），
并在 `tests/test_p24_update_npm.py` 里钉死。

## 多群/多会话：通道三元组（v2.34）

当灵枢同时服务多个群聊 / 多个会话时，记忆默认混在一起会串台。v2.34 引入**通道三元组**（channel / group_id / user）做记忆隔离与跨群共享：

- **同一群共用一份群记忆**：`group_id` 相同的会话共享群级记忆（群规、群梗、共同的约定）；每个用户自己说过的话另存用户层，互不污染。
- **跨群记忆**：`channel remember` / `channel recall` 操作"全局通道"记忆——想在所有群/会话间共享的记忆（你的偏好、主人的规则）写进这里，哪个群都能想起来。
- **按人回忆**：`channel user <id>` 回忆某个用户在群里说过的事——做群管、画像、个性化回应都用得上。
- **startup 注入自动带上通道**：会话在哪个群、以谁的身份启动，注入包就是那个通道的视角；主记忆库（`startup` 不带通道）仍是全局兜底。

### 群友隐私保护（v2.35）

群聊里不只有你一个人——把别人的话记进记忆库并让 AI 拿去回忆，本质是拿别人的数据。v2.35 加了一道**本人授权门控**：

- **本人可查可删**：任何用户可以查看自己被记了什么（`channel privacy status` 看自己）、要求删除；
- **第三人需授权**：回忆/查询**别人**在群里说的内容，需要对方曾用 `channel privacy grant` 授权过（按用户维度记录在 `consent.json`）；未授权时命令被拒（退出码 4，`PrivacyDenied`），并明确告知哪位用户未授权；
- **主人也不豁免隐私门控**：owner/admins 只能管理命令（授权/撤销/查看状态），不能替别人授权自己去看——隐私门控对所有人一致；
- **随时撤销**：`channel privacy revoke <用户>` 撤销授权，之后该用户的数据立即回到"第三人不可查"状态。

命令速查：

| 命令 | 作用 |
|---|---|
| `channel remember "内容" --group <id> [--user <id>]` | 写群级/用户级记忆 |
| `channel recall "关键词" --group <id>` | 从指定群通道回忆 |
| `channel user <id>` | 回忆某用户在群里的记录 |
| `channel privacy status [--user <id>]` | 查看自己/指定用户的授权状态 |
| `channel privacy grant <用户>` | 本人授权（同意被记忆与被回忆） |
| `channel privacy revoke <用户>` | 撤销授权 |

## 主人鉴权（v2.34）

`config.json` 里配置 `owners`（主人）与 `admins`（管理员）名单后，危险/管理类命令只对名单内身份放行：非主人执行管理命令返回退出码 3，避免群里任何人都能指挥灵枢改人格、删记忆。主人/管理员名单只存本机，不上传。

**信任边界（务必知晓）**：owner/admin 鉴权依据的是命令行 `--user` 参数，这是**宿主自声明**的身份，没有任何凭证校验——灵枢选择信任宿主进程（AstrBot 插件 / 自建 bot 框架）传入的身份是真实、未被伪造的。因此：

- **纯本机命令行**（不带 `--user`）不受任何限制，默认可信；
- **本机单人环境**下风险可接受：能登录这台机器的人本来就能直接改记忆库文件，`--user` 伪造没有额外收益；
- **多用户共享机器或宿主暴露命令执行面**（如把 shell 交给群友、宿主插件有命令注入漏洞）时，`--user` 可被冒充，owner 门控形同虚设——此时请自行保证宿主不被越权调用（收紧宿主权限、不把 shell 暴露给不可信方），或在宿主侧加共享密钥/签名校验后再传给灵枢。

## AstrBot 插件（bridge v0.2.2）

除 DSH / Trae 之外，灵枢还提供了一个 **AstrBot 插件**（`scripts/astrbot_plugin_lingshu/`，详见[插件 README](scripts/astrbot_plugin_lingshu/README.md)），把灵枢接进 AstrBot 的 QQ/微信等群聊场景：

- 以 **subprocess 进程隔离**方式调用 `brain.py`，灵枢崩溃不影响 AstrBot 主进程；
- 自动携带**通道三元组**（channel + 群 id + 用户 id），群记忆隔离与隐私保护开箱即用；
- **人格只读**：桥接刻意不调用 init/startup，不注入人格；人格初始化请在**本机 CLI** 执行；
- 支持以 AstrBot 指令直接触发 `remember` / `recall` / `同意` / `拒绝` 等命令；
- 可选 `auto_recall`（召回注入）与 `auto_capture`（自动写回，**默认关闭**）。

**安全默认值与开启风险**：

| 配置项 | 默认 | 开启前须知 |
|---|---|---|
| `auto_recall` | 关 | 只读召回，按同群分享授权过滤，风险低 |
| `auto_capture` | 关 | 会把群友聊天原话长期落盘；写回前检查用户 `consent`，敏感词拦截 + 节流；请先完成群内隐私告知 |
| 隐私查询门控 | 恒开 | `recall --asker/--target`：未授权返回退出码 4，消息不回显目标标识 |

安装：把 `scripts/astrbot_plugin_lingshu/` 整个目录放进 AstrBot 的插件目录，重载插件即可；配置里指定 Python 路径与灵枢技能目录（含 `scripts/brain.py`）。

> **桥接同步提醒（#6）**：插件目录带自校验（`CHECKSUMS.json`，可用 `make_checksums.py --check` 验证），但它**不包含**在根 manifest 的 `apply_update` 自动更新范围内。技能本体升级后，桥接目录可能仍是旧版——请手动重新复制 `scripts/astrbot_plugin_lingshu/` 到 AstrBot 插件目录，或在 CI/发布流程中同步两边的版本号（`check_version.py` 会校验插件 `metadata.yaml` 与根 `package.json` 的次版本一致）。

## 可靠性设计

- **跨进程写锁**：并发写入用独占锁互斥，不丢更新
- **损坏行自愈**：JSONL 里出现坏行自动分拣——好行写回，坏行挪到 `.corrupt`，绝不静默丢失
- **备份/恢复**：`backup` 打包整个记忆库（含 verbatim/ 与 skills/），自动修剪旧备份；`restore` 恢复前先留现状备份，校验 zip 合法性并防 zip-slip 路径穿越
- **只读降级**：沙箱写盘被拒时自动降级为只读注入，已有的记忆照样带回；`--home` 支持把数据目录迁到工作区
- **数据目录可迁移**：目录解析优先级为 环境变量 `BRAIN_MEMORY_HOME` > 指针文件 `~/.brain-memory/.home` > 默认位置；面板「诊断」页的「数据目录」卡片可一键把整库复制到新位置并写好指针（重启生效，旧目录保留）
- **原子写入**：所有文件写入走临时文件 + `os.replace`，不会出现写一半的脏文件
- **运行日志可见**：锁冲突、内部异常、解析报错写进 `lingshu.log`（滚动截断），面板「日志」页按级别查看——出问题先看这里，不用翻文件

### 底层保险：写前快照 + 写后校验 + 自动回滚

`save_all()` 是全项目**最高危的写入口**：它按 layer 把整批记录分写回
`hippocampus / cortex / dust` 三个文件，一旦读写之间丢记录或层名写错，**整层被覆盖**。
项目里有 **17 个公开函数**最终都落到它（`remember` / `forget` / `fold` / `purge` /
`trash_restore` …）。

所以加了 `scripts/safety_net.py`，接在 `save_all()` 上：

```
写前 O(1) 硬链接快照  →  执行写入  →  写后校验  →  失败自动回滚
```

**借鉴来源**：ARIES 的 undo 日志、rsnapshot / Time Machine 的**硬链接快照**
（`os.link()` 零拷贝、天然 COW）、crash-only software 的"恢复放常路"、
SQLite WAL / LMDB 的"单写者 + 原子替换"。

**为什么硬链接就够**：本项目写盘一律"写临时文件 → `os.replace`"。替换只改目录项，
老 inode 不动，所以事先 `os.link` 出来的快照**永远保留旧内容**，不需要复制字节。

**校验三项**：JSON 每行可解析、末行完整（没被截断）、**层级自洽**
（记录自带 `layer` 必须与它所在文件匹配）。最后这条能抓住"整批记录被灌错层"的 bug——
那种错 **JSON 仍然合法**，只查语法永远查不出来。

**关键坑**：硬链接快照**只在原子替换下成立**。若某处代码**就地截断写**（`open("w")`），
改的是共享 inode，**快照会跟着一起被毁**。所以快照时记 `sha256`，
**回滚前先验指纹，不符就拒绝回滚**——拿脏快照覆盖比不回滚更糟。

配置：`safety_snapshots` / `safety_verify` / `safety_keep`（默认留 20 份）。
全程 **fail-open**：保险自身出错绝不阻断主写入。

### 只移不删：垃圾桶与备份分层

**用户定的规矩**：AI 不删除任何文件，只把"该删的"移到指定位置，由用户自己清。

| 场景 | 去哪 |
|---|---|
| 程序目录里待删的文件/目录 | `垃圾桶/`（`brain.py trash <路径> --why "原因"`） |
| 备份被分层策略"修剪"掉的旧包 | `<备份目录>/.pruned/` |
| 超保留份数的写前快照 | `<记忆库>/.safety/.pruned/` |

三处都带时间戳，代码里**没有任何 `unlink` 清理逻辑**；`垃圾桶/` 已进 `.gitignore`，
不进版本库、不被发版带走。

### 软删除台账：purge 也能捞回来

`purge` 是唯一**物理删除**记忆的操作。删前先把整条记录追加进 `<记忆库>/trash.jsonl`
（含 `deleted_at` / `deleted_layer` / `delete_reason`）：

```bash
python scripts/brain.py memory trash-list              # 看留底
python scripts/brain.py memory trash-restore <id>      # 恢复回热层
```

成本一条几十到几百字节，比整库备份便宜得多。

### 备份策略：按小时、分层保留、包内清单

- **按小时驱动**：`backup_interval_hours`（默认 6）。**不是"一天一次"**——旧设计只在当天
  第一个回合跑一次，实测当天后续写入缺 17%。
- **变更量驱动**：`backup_min_new_records`（默认 50），写得多就补一次。
- **分层保留（GFS）**：`backup_keep_hourly`(6) / `daily`(7) / `weekly`(4)，
  **最新一份永不删**；被修剪的移入 `.pruned/`。
- **包内清单**：每个包写 `_backup_manifest.json`（文件数 / 各层记录数 / 版本 / 时间），
  不必解包就能核对。
- **疑似空壳按记录数判**：`records < max(10, 当前库 20%)` 即标可疑并禁用恢复
  （只看字节大小会漏掉"3327 B 只有 4 条"的假备份）。
- **恢复前健全性检查**：`restore` 会先 testzip、坏包自动回退到上一份完好备份，
  且**恢复前自动给现状打一份备份**。

### 水位估算标定（盈不足）

水位估算模型是 `tokens = chars / ratio + overhead`，**两个未知数**。
宿主偶尔会给出**真实 token 数**，那就是"盈不足"（《九章算术》双假设法）的两次观测：
用 ≥2 组 `(chars, tokens)` 做**最小二乘同时反推 ratio 与 overhead**，
比把 overhead 写死 18000 准得多。

- 插件限流记录样本（60 秒内且字符差 <2000 不记），拟合写 `<记忆库>/token-calib.json`；
- **合理性闸**：ratio 0.5~5、overhead 0~200000、字符跨度 ≥2000，不过就退回配置默认；
- `python scripts/brain.py token-calib [--refit]`：看样本，并用**同一公式独立重算**与
  插件写入值**对账**——两边不一致会明确报错（补"JS 侧没法单元测试"的保险）。

### 数据目录护栏

**盘符根、用户主目录本体、桌面/文档/下载/图片/视频/音乐/OneDrive 一律拒绝**当记忆库
（`safety.assert_safe_home`）——真实事故就是这些目录被整片清空、库跟着一起没。
逃生阀 `BRAIN_MEMORY_ALLOW_UNSAFE_HOME=1`（放行但警告）。

**备份默认跨卷选址**：`BRAIN_MEMORY_BACKUP_DIR` > 别的卷 `brain-memory-backups` >
`<记忆库>/backups`——同卷同目录的备份会被同一次事故一起带走。

### 常见问题：写操作报「文件被占用，请稍后重试」

- **现象**：面板保存人格/配置等写操作偶发 400 错误。
- **原因**：Windows 上某个进程短暂持有记忆库文件（`~/.brain-memory/*.json`）的读句柄（常见：杀毒软件实时扫描、系统索引器），原子替换需要等它松手。
- **排查**：① 看面板「日志」页有没有对应异常记录（v2.29 起写失败必落日志，含路由与异常详情）；② 高频复现可用 Sysinternals 的 `handle.exe ~/.brain-memory` 查谁占着句柄；③ 反复出现可把记忆库目录加入杀毒软件排除列表。
- **恢复**：稍等几秒重试即可——写路径带约 10 秒的指数退避重试，瞬时占用通常会自愈；持续失败才说明句柄被长期持有，按上面②定位占用者。

### 常见问题：AI 工具的自动审批拦截灵枢命令（报 invalid character '*'）

- **现象**：在 Trae 等 AI 编程工具里，AI 助手执行 `python scripts/brain.py <任意子命令>` 被自动审批系统拦截，报 `Automatic approval review failed: invalid character '*'`。用户手动在终端里跑同样的命令完全正常。
- **原因**：这不是灵枢的问题。报错格式（`looking for beginning of value`）来自审批服务自身的 JSON 解析器（Go 风格），即审批系统在审查这个动作时**自己内部崩溃了**，与命令内容、路径中文、脚本名均无关（已用对照实验验证：空脚本、只读命令能过，凡真正执行灵枢引擎的命令都被拦）。灵枢是纯 Python 标准库，命令与文档里的 `*` 只是 Markdown 加粗语法。
- **怎么办**：
  1. **让用户手动跑**：AI 把要执行的命令原样列给用户，用户在自己的终端（PowerShell / CMD）里执行，把输出贴回来即可；
  2. **走可视化面板**：`python scripts/brain.py panel` 后在浏览器里操作——做梦、记忆增删、复核全部有界面按钮，完全不经过审批系统；
  3. **重启 AI 工具重试**：审批故障通常是会话级/临时性的，换个会话或重启客户端后可能恢复；
  4. **不要让 AI 绕过**：改名脚本、拆字符串拼命令等手段既不可靠也违反工具安全策略。

### 常见问题：Windows 上 `python` 的退出码读不到（`%ERRORLEVEL%` 恒 0）

- **现象**：在 CMD 里跑 `python scripts/brain.py doctor` 后用 `%ERRORLEVEL%` 判断结果，永远是 0；PowerShell 里 `$LASTEXITCODE` 同样不可靠。
- **原因**：`python` 命令常常解析到 `python.cmd`（py launcher / Store 别名 / 某些环境管理器生成的包装脚本）。`.cmd` 只做转发，**不会把子进程退出码传回**，于是调用方看到的是包装脚本自己的 0。
- **怎么办**：需要判断退出码时，**用 `python.exe` 的完整路径**（`where python` 找到它）：

  ```powershell
  & "D:\ServBay\packages\python\current\python.exe" scripts\brain.py doctor
  $LASTEXITCODE   # 现在能拿到真实值：0 正常 / 1 WARN / 2 FAIL
  ```

  或者用 Python 侧间接判断：`python scripts/brain.py doctor --json`，读 JSON 里的 `ok` 字段（不依赖退出码）。

## 脚本 vs 模型：谁在真正干活

**先打消一个误会：装上灵枢不等于自动拥有类人脑智能。** 这套脚本是「存储、调度、数学计算」；真正的「智能」——合并记忆、理解情绪、提炼知识——仍然靠你接入的大模型。谁干什么，边界如下：

| 工作 | 谁干 | 说明 |
|---|---|---|
| 存储 / 衰减 / 强化 / 分层搬运 | **脚本** | 艾宾浩斯曲线、蔡格尼克、峰终、杏仁核劫持上限等全是公式，模型只负责触发命令 |
| 模糊回忆 | **脚本** | 字符二元组 / 词元加权，不需要模型参与（也因此是字面匹配，不是向量语义检索） |
| 上下文注入包（startup 输出） | **脚本** | 纯拼装，模型照抄即可 |
| 重放 → 碎片分组（dream） | **脚本** | pending 分组是启发式完成 |
| 碎片合并成新记忆、判断要不要 | **模型** | 这一段是幻觉高发区：合并错误、编造就发生在这里 |
| 情绪事件的解读（emotion evaluate） | **模型** | 小模型会把中性对话判成愤怒/狂喜，或看不出反话 |
| 提炼知识库（knowledge tidy） | **模型** | 小模型容易编造结论，直接沉淀成知识 = 幻觉落盘 |
| 技能自检（skill check） | **模型** | 全靠模型读正文挑毛病 |

所以：**脚本保证"记下来了、想得起来、删得掉、片段不丢"；模型决定"记得准不准、合并对不对、情绪认不认"。** 想提高"记得准"，就换更强的模型或动 `config`。

## 模型适配与档位

灵枢不在脚本里硬堵模型能力，而是提供一个**档位开关**，让高风险自动能力按模型强弱开合：

| 能力 | 7B+ / 云端 | 1.5B–3B 小模型 |
|---|---|---|
| 记忆增删查（remember / recall / list） | ✅ 完整 | ✅ 完整（脚本本身零模型依赖） |
| capture 原样封存 | ✅ | ✅ |
| dream 重放分组 | ✅ | ✅（启发式部分可用） |
| dream --apply 合并结果 | ✅ 完整用 | ⚠️ 建议关：合并错误 = 幻觉记忆落盘 |
| knowledge tidy | ✅ 完整用 | ⚠️ 建议关（或强制走待审核） |
| emotion evaluate / mirror | ✅ | ⚠️ 易判错情绪，改用手动 `emotion feel` |
| skill check | ✅ | ⚠️ 结果可信度低 |

**小模型模式**（`config set model_tier small`）做的事：`startup` 注入包里追加「小模型模式」约束——不要自动 `dream --apply`、不要自动 `knowledge tidy`（产出须先 `knowledge review` 过目）、情绪评估改用手动 `emotion feel`。这只是**注入提示**，约束力取决于模型听话程度；3B 以下仍会漏执行，别指望它当保险丝。恢复：`config unset model_tier`（回到 auto）。

**输出容错**：所有需要模型产 JSON 的入口（`dream --apply`、`knowledge tidy --apply`）都做了**容错解析**——先按标准 JSON 读，失败再去掉 ```json 代码围栏，再失败截取第一个配平的 `{...}`，实在读不出来会**明确报错并返回退出码 2**，不再静默吞掉。解析失败时报错里带文件路径与内容开头，方便直接排查。

## 接入大模型（Ollama 示例）

灵枢是命令行工具，接入哪家模型由你决定，它只负责被调用。以本地 Ollama + qwen2.5 7b 为例：

```bash
# 1) 你家 Agent 是一次会话的调度者，为每次会话先跑三条
python scripts/brain.py startup --query "$USER_MSG"        # 把记忆注入提示前面
python scripts/brain.py remember "$USER_MSG" --source user # 用户说的入模记忆
# 2) 之后正常对话；水位到了再触发整理
python scripts/brain.py check-context --used 68            # 60 清点 / 75 做梦 / 90 封存
python scripts/brain.py dream --auto
```

Ollama 侧只需要一份 `Modelfile`，把"调用脚本"写进 system prompt 让它自己看情况执行：

```dockerfile
FROM qwen2.5:7b
SYSTEM """你运行在本地，有记忆系统「灵枢」。每轮先按需执行：
- 新会话第一轮：运行 startup --query "本轮主题"，把输出原样作为你的记忆前缀。
- 用户说了值得记的事：运行 remember "<原话>" --kind fact|preference|emotion --importance 1-10。
- 需要回忆：运行 recall "<关键词>"。
- 上下文快满：运行 check-context --used <已用百分比>，并按提示配合。
如果命令没有可执行环境，就按 SKILL.md 的规则口头执行，绝不乱编记忆。
"""
```

更省事的替代：直接把这套框架装成 Agent 技能（`skill install` 全局化后，DSH / 本地 Agent 每会话自动读到 SKILL.md，按里面的机制走）。

## 规模上限与归档

记忆以 JSONL 纯文本存储（hippocampus/cortex/dust 等），**没有数据库索引**：

- `recall` 模糊匹配要遍历全部记录，条数上万后每次命中会变慢（本地为毫秒级→百毫秒级，仍在可用区间）。
- `dream` 会自动把一批短期记忆打包喂给模型，短期记忆越多，当次 token 消耗越大。

**建议的养生方案**：每周一次 `backup`（默认保留最近 20 份，自动修剪）；沉眠记忆交给**冷热自动归档**（每次做梦顺带雪藏进 archive 层，或 `archive run` 手工触发），不用再手动逐条删除——需要时 `archive search` / `archive restore` 找回；知识库定期 `knowledge review` 确认。真到数据膨胀影响手感的层级，把 `--home` 指向新目录再 `restore` 最近备份，旧目录留档。

## 技能名为什么是 lingshu

`SKILL.md` 的 frontmatter 是 `name: lingshu`（中文名放在 `title: 灵枢`）。原因是 **DSH 的文件系统技能发现只认 kebab-case 名字**，中文 `name` 会被静默跳过——表现就是"装了却看不到 / 像被改名"。

- 安装时用中文名或英文名都行：`skill install 灵枢 --from <本目录> --yes` 与 `skill install lingshu ...` 等价，目录与 frontmatter 统一落成 `lingshu`；安装目标自动选 **DSH 的 `~/.dsh/skills`**（没有就回落 Trae 的 `~/.trae-cn/skills`）。
- 装完想确认有没有被认出来：`python scripts/brain.py skill list --global`，正常显示 `✓`；若是旧版中文目录会标 `✗ 目录名/name 不是 kebab-case，DSH 会跳过`，跑一次 `skill uninstall lingshu`（会连旧目录一起删）再装即可。
- 手动拷进 DSH 技能目录时，**目录名和 frontmatter name 都要用 kebab-case**（`lingshu` / `lingshu-lite` / `lingshu-tiny`），路径是 `~/.dsh/skills/lingshu/`。

## 如何更新灵枢

### 发布新版本的标准流程（维护者）

```bash
# 0. 一次性：安装 git 钩子（pre-commit 版本守卫 + pre-push tag 守卫）
python scripts/check_version.py --install

# 1. 改完代码后：生成/刷新发布清单（内置 version 与 SKILL.md 一致性校验）
python scripts/make_manifest.py
# 2. 升 SKILL.md 的 version，并在 CHANGELOG.md 写好对应小节（如 "## v3.15 — 标题"）
#    ——这两步由 pre-commit 钩子强制：代码变更不升版本、升版本没写 CHANGELOG 都会被拒绝
# 3. 提交
git add -A && git commit -m "v3.15 …"
# 4. 推送 main（--follow-tags 确保 tag 跟着一起推）
git push --follow-tags gitee main && git push --follow-tags origin main

# 5. 核对 tag 与版本是否对齐（也可以手动跑）
python scripts/check_tag.py --check
```

> **tag 守卫（pre-push）**：推 `main` 时若当前版本还没有 `vX.Y` tag，钩子会自动在 HEAD
> 打一个带注释的 tag，并**拒绝本次推送**，提示改用 `git push --follow-tags`。
> 这样「仓库很久没打 tag、市场版本说明一直停在旧版本」不会再发生。
> 应急跳过：`LINGSHU_SKIP_TAG_CHECK=1 git push ...`（不建议）。

> **Release 自动创建**：`.github/workflows/release.yml` 在推送 `v*` tag 时触发，
> 自动把 CHANGELOG 对应版本小节写成 GitHub Release 正文。
> **这一步不能省**：插件市场（dsh-market）的「版本说明」读的是
> `awesome-dsh-plugin` 目录站抓取的 **GitHub Release**，不是 git tag；
> 只打 tag 不建 Release，市场会一直显示上一次 Release 的说明。
> 目录站每天抓一次，所以 Release 建好后，市场通常要等下一次抓取才更新（market 自身另有 1 小时缓存）。
> 手动兜底：`gh release create v3.18 --notes-file <(sed -n '/^## v3.18/,/^## v3.1[0-7]/p' CHANGELOG.md)`。

- 具体保留下来的（都在数据目录，不在技能目录）：人格 `persona.json`（含初识与演化历史）、记忆 `hippocampus.jsonl` / `cortex.jsonl` / 归档、知识库与笔记、情绪与欲望状态、记忆关联 `assoc.jsonl`、梦报告 `dreams/`、运行日志 `lingshu.log`、**你自己写的技能 `skills/`**、**扩展模块 `extensions/`**、长期规则 `lingshu.user.md`、`config.json`。

## 核心算法一览

不用大词，逐条说清"算什么、怎么算、参数在哪"。

| 算法 | 用在哪 | 怎么算 |
|---|---|---|
| **艾宾浩斯式遗忘** | 记忆衰减 | 每条带 `stability` 半衰期，`retention = f(距上次访问, stability)`；被想起时 `stability ×2.6`（首次）/ `×1.8`（之后）/ `×1.2`（顺带想起） |
| **五元复合打分** | `recall` 排序 | `相关度×0.55 + 新鲜度×0.10 + 重要性×0.35 + 核心偏置×0.20 + 首因×0.03`，权重全在 `config.weights` |
| **词面模糊匹配** | 中文召回 | 中文切**字符二元组**、英文/数字按词；IDF 加权后算相关度（`mode=fast` 纯词面，`auto` 会叠语义向量） |
| **查询词覆盖率门槛** | `prior` 精度 | 命中查询词数 / 查询词总数 ≥ 35% 且 ≥2 个才展示，否则**弃权** |
| **字符二元组相似度** | 去重 / 冲突检测 | Jaccard：`|A∩B| / |A∪B|`；≥0.86 判重复、0.55~0.86 判"说法变了"（触发 supersede 或冲突待审） |
| **否定极性判定** | 错卦 | 显式 `avoid` 标记优先；否则正文正则匹配否定词表 |
| **六位状态编码** | `shape-audit` | 六个二元特征打包成 6 位整数 → 64 格；配三条领域不变量 |
| **最小二乘（双假设）** | 水位标定 | 拟合 `tokens = a + b·chars`，`ratio = 1/b`、`overhead = a`；带合理性闸 |
| **哈希链** | 防篡改 / 定位损坏 | 每条记录带 `h`（本条哈希）与 `p_h`（上一条哈希），**每个文件独立封链**；校验时逐文件重算 |
| **原子替换** | 所有写盘 | 写 `*.tmp` → `os.replace`，Windows 占用时指数退避重试 |
| **硬链接快照（COW）** | 底层保险 | `os.link()` 建快照（O(1) 零拷贝），配合原子替换天然写时复制；回滚前用 sha256 验快照未污染 |
| **分层保留（GFS）** | 备份修剪 | 小时层留 N 个、每天留 1 个、每周留 1 个，取并集；最新一份永不删 |
| **RRF 式多源融合**（简化） | `prior` 聚合 | 知识 > 教训 > 笔记 > 记忆 分级优先，再按字符二元组相似度去重 |
| **双轴情绪模型** | 情绪标签 | 效价 v × 唤醒度 a → 13 档人话标签（Russell 环形模型） |
| **情绪半衰期** | 情绪消退 | `EMOTION_HALF_LIFE = 6h`；抑制上限 0.4 |
| **欲望衰减** | 六欲 | 默认 60、每日 −3、地板 8；情绪按映射表反向喂养（如「喜」→成就欲 +6） |
| **人格漂移 EMA** | traits 演化 | 新观察权重 0.6、攒够 5 次证据才动、30 天无新证据回归基线、单次采纳最小位移 0.15 |

## 边界

灵枢管**人格/情绪/关系**，DSH 管**工作/项目**——每日用 `sync dsh` 把灵枢日志摘要自动进 DSH 当日日志，两边各记各的，不重复、不漂移。
