## 任务清单 B：人格面板 ↔ 记忆/笔记/知识库同步（用户新增需求）

> 用户要求：人格面板要跟着记忆、笔记、知识库里的性格/人格标签/喜好讨厌同步。调研六项目（perch/muu/Herta/language-guard/whale/aiyayi）提炼的最佳实践。

### 设计原则（借鉴结论）

- **人格是派生品，不是表单**（perch）：人格状态由记忆/事件派生，手动编辑也落为"事件"，保证一致性。
- **漂移要可度量**（muu）：人格变化设步长上限 + 锚点限幅 + driftReport 稳定度分（0~100）。
- **人格与记忆分离 + 确认闸门**（whale）：从记忆归纳的人格特征先待确认，用户采纳才进 persona——防记忆幻觉污染人格。
- **关键约束多点驻留**（language-guard）：人格守则注入在注入包头/工具文档后/尾多处，周期自检。
- **两级注入**（aiyayi）：常驻核心人格 + 按需档案树；AI 可自主整理人格档案。

### 任务

- [x] **人格画像自动归纳**：做梦/learn 时扫描记忆里 kind=preference/relationship/mistake 与笔记、知识条目，归纳「性格标签/喜好/讨厌/在意的人」候选特征（带 source_ids 证据链），写 `persona_pending.jsonl` 待确认。
- [x] **面板人格页「画像建议」卡**：展示候选特征 + 证据（点开可跳到来源记忆/笔记/知识条目），一键采纳（写 persona）或忽略；采纳/忽略都记 evolution 日志。
- [x] **人格漂移度量**：persona 变化（自动归纳 + 手动编辑）都记事件流（追加不可改），算步长限幅；面板显示稳定度分（借鉴 muu driftReport）；锚点=初识时 personality 快照。
- [x] **记忆↔人格反向引用**：persona 的 likes/dislikes/traits 每项可带 `sources: [memory_id/note_id/knowledge_id]`，面板人格页每项显示"来自哪条记忆"，recall/forget 不撕链。
- [x] **startup 注入人格一致性自检**：注入包尾部加一行人格摘要（当前 traits/likes/dislikes 摘要），与 language-guard 同构，防长会话人格走样。
- [x] **人格改动"先生效后告知"流**（用户新增，覆盖原"草稿→审核"方案）：人格页编辑改动直接生效（不弹确认框打断），但①被改的字段标高亮颜色（diff 视觉，标本次改了什么）；②**首页概览出现「人格有变动」提示卡**，点它 = 已确认浏览（关闭概览显示）并跳转到人格页；③人格页有变更历史记录，每条可**滚回**（走既有快照机制）；④概览提示是否已读要持久化（重启面板不再重复弹）——灵感来自 /api/persona/changes-viewed 已有端点。
- [x] **人格变更审计链**（借鉴 dsh-soul）：每条人格变更记录三元组「触发事件 → 变更内容（字段旧值/新值）→ 来源证据（记忆/笔记/知识 id 或"手动编辑"）」，与上面编辑审核流共用一套存储，面板可按时间线查看。
- [x] **遗忘可纠正**（借鉴 dsh-fish-soul 艾宾浩斯遗忘）：记忆 recall 命中时除强化 retention 外，支持"纠正回升"——AI/用户判定某条被淡忘的记忆仍重要时，可一键把 retention 拉回并重置衰减计时；mistake/relationship 类记忆默认更抗遗忘（衰减半衰期更长）。
