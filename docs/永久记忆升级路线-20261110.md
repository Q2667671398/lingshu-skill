# 灵枢 · 永久记忆升级路线

> 生成日期：2026-11-10 · 触发：用户分享「渊星永记」ASI超级智能永久记忆研究笔记，
> 对照灵枢 v2.94 现状做差距盘点，分 P0/P1/P2 三档落地。

---

## 一、渊星永记方案 vs 灵枢现状 · 差距盘点

### 灵枢已做到（不用改）

| YX 方案特性 | 灵枢对应实现 | 代码位置 |
|---|---|---|
| 分层存储 | hippo（快速易衰）→ cortex（稳定）→ dust（淡忘轮廓）→ **archive（冷存储原文永久保留）** | `core.py ARCHIVE_LAYER` |
| 矛盾标记 | 启发式 `detect_conflicts()`，实体聚合 + 改口信号判定 | `memory.py L24` |
| 版本链雏形 | `superseded_by` 链（观念取代后旧记忆不删，只默认跳过） | `memory.py L1153` |
| 冷集完整原文 | archive 层**永不自动删除**，只做冷存储 | `core.py ARCHIVE_MIN_AGE_DAYS=30` |
| 隐私边界 | recall 通道隔离 + `_channel_visible()` + target_user/asker 隐私防护 | `memory.py L1155-1166` |
| 核心规则锁 | persona.json 独立文件，单独层存储不进 JSONL 热集 | `persona.py` |

### 灵枢真缺口

| # | 缺口 | 灵枢现状 | 代码位置 | 实质影响 |
|---|---|---|---|---|
| G1 | **双重时间衰减太重** | `recency 权重 0.25` + `score *= max(0.5, 0.5^(age_days/30))`（每月半衰期） | `memory.py L1196 + L1213` | 3 个月前的核心偏好被压到 50%，语义完全正确但分数低，容易被新临时记录挤下去 |
| G2 | **Core 人格记忆无单独加权** | persona 层相关记忆和 hippo 临时记录同权重 | `memory.py L1196` | 长期核心规则容易被近期临时记录挤下去 |
| G3 | **冷集不自动补召** | `include_archive=False` 默认，热集空了不会自动捞冷集 | `memory.py L1122` | archive 里的永久记忆除非手动开开关，否则躺着睡 |
| G4 | **无语量 Dense 召回** | 纯 IDF 二元组关键词 | `memory.py L1193` | "我之前提过那个关于并发的方案"这类模糊查询易漏召 |
| G5 | **无图谱关系层** | entities 字段只做精确命中加分 | `memory.py L1205` | 项目 A 迭代自项目 B 的关联，跨迭代召回靠运气 |
| G6 | **persona 无版本快照** | dream.py 微调 traits 直接改 json，无历史快照 | `dream.py _drift_trait` | 人格漂移无法回滚到某次会话前的状态 |

### 不该抄的（打破零依赖定位）

- pgvector / Neo4j / Milvus——灵枢主打"pip install 直接跑，纯标准库"
- LangGraph / AutoGen——灵枢是单 Skill 给 DSH 会话用，不是多 Agent 编排框架
- LoRA 微调记忆——主力记忆必须是外部可检视、可回溯的 JSONL，不是权重里的黑盒

## 二、落地路线图

### P0 · 立即改（零依赖，改 3 处）

> 预计改动：`memory.py recall()` 约 20 行、`dream.py` 约 15 行、`core.py DEFAULT_CONFIG` 5 行。

#### P0-1 recall 排序权重重构（改 `memory.py L1196 + L1213`）

- 权重表调整（`core.py DEFAULT_CONFIG.weights`）：
  - `relevance: 0.55`（不变）
  - `recency: 0.25 → 0.10`
  - `importance: 0.20 → 0.35`
  - 新增 `core_bias: 0.20`
- **删除 L1213 那层双重时间衰减**（`score *= max(0.5, 0.5 ** (age_days / 30.0))`）——永久记忆不该有"每月半衰期"
- recall 里加 persona 命中加权：记忆 tags/entities 含 persona trait 关键词（读 persona.json traits 字段）时 × `(1 + weights.core_bias)`

#### P0-2 冷集自动补召（改 `memory.py recall()` 末尾）

- recall 流程改成：
  1. 先跑热集 Top-K
  2. 如果 Top-K 均分 < 0.10（语义相关度普遍很低），**自动** `include_archive=True` 重跑一次并集 rerank
- 面板和 CLI 对 archive 的默认搜索按钮不动，只改 recall 内部自动兜底

#### P0-3 persona 快照（改 `dream.py`）

- 每次 dream 微调 traits / 修改 persona 前：
  1. 把当前 persona.json 追加进 `persona_snapshots.jsonl`
  2. 带字段：`version`（递增 int）、`ts`、`action`（drift/rollback/edit）、`persona`（完整深拷贝）
- 新增 CLI 子命令 `brain persona-rollback --version N`（或面板加「人格版本管理」tab）

---

### P1 · 中期（可选依赖 Ollama，不装就退回纯关键词）

> 可选：环境变量 `LINGSHU_EMBED_URL=http://localhost:11434/api/embeddings` 存在时启用；
> 未配置则自动退回纯 IDF 关键词，不破坏零依赖定位。

#### P1-1 cortex/hippo 每条记忆加 embedding

- 每条 JSONL 记录加可选字段 `embedding: [float, ...]`（维度=模型输出维度）
- 写入时异步生成（可选，Ollama 可达则生成，不可达跳过）
- recall 增加 Dense cosine + IDF 混合召回：各自 Top-K 并集 rerank

#### P1-2 rerank 可插拔

- 可接入本地 reranker（Ollama 上的 small reranker）
- 未配置 reranker 则用简单加权合并

---

### P2 · 长期（标准库图谱雏形）

> 保持零依赖，用 JSONL 存 S-P-O 三元组。

#### P2-1 新增 relations.jsonl

- 每行：`{"s": "...", "p": "迭代自|依赖|引用|冲突", "o": "...", "ts": 1234567890, "source_memory_id": "..."}`
- 规则抽取兜底：实体=项目名/文件名/已知概念；关系=从 tags/entities + keywords 自动推

#### P2-2 检索关系链扩召回

- recall 命中实体时，拉取 relations 里 S 或 O 等于该实体的三元组，把关联记忆并入候选集

## 四、验收清单（每档做完跑一遍）

- [ ] **NIAH 埋针测试**：3 个月前的核心偏好（如"项目 A 用 PostgreSQL"）在 500 条噪声下能召回到 Top 3
- [ ] **核心 vs 临时**：核心规则（persona traits）在召回排序里持续稳定出现在 Top 5，不被 1 个月内的临时记录挤下去
- [ ] **冷集补召**：热集 Top-K 均分 < 0.1 时，archive 里的永久记忆自动补进来
- [ ] **回滚可用**：`persona-rollback --version N` 能恢复到某次 dream 前的状态
- [ ] **零依赖不破**：不装 Ollama、不装 pgvector 时，灵枢仍然能跑，只是退回纯关键词召回
