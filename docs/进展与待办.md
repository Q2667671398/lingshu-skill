## 二、待办（按优先级）

### P1 · 值得下一个版本做

1. **engine 副本双份维护收敛**（33×2 脚本 + 11 份文档）：目前靠 `sync_engine.py` 保证一致，漏跑就红。方向：发布时生成副本、副本不入库。**验收**：删掉 `scripts/astrbot_plugin_lingshu/engine/` 后仍能出一条可用的插件 zip。
2. **覆盖率报告 + 性能基线**：`bench.py` 存在但从不进 CI；40 个测试文件按特性命名，看不出模块覆盖。**验收**：本地能出一条覆盖率报告（不进 CI 以免考核数字），`bench.py` 能在隔离 HOME 跑出 remember/recall/inject/doctor 四组数字并有历史对比。
3. **破坏性操作确认逻辑统一**：`restore` 自己写了一套确认，`purge` 用 confirm token，两套规则并存。方向：`safety.confirm_destructive()`（TTY 询问 + 非 TTY 必须 `--yes`；先备份再问，拒绝时删掉本次备份）。**验收**：两条路径都走同一个函数，且都有"影响面清单"输出。

> 原 P1-4「`check_tag.py` 过严，卡住版本后的文档提交」已在 **v3.50** 解决：改成「tag 是 HEAD 祖先且确实打在这个版本上」即放行，不再需要 `LINGSHU_SKIP_TAG_CHECK=1` 绕过。

### P2 · 结构性债

4. **关键路径异常计数**：全仓 327 处 `except Exception`，"失败即降级"是有意设计，但关键路径（恢复/备份/元数据/锁）吞掉真缺陷。**验收**：`doctor` 能报"最近七天各类被吞异常次数"（`failures` 账本已有数据，只差聚合展示）。
5. **默认值只在代码里定义一次**：文档里写死过"备份默认 `D:/brain-memory-backups`"，代码改跨卷选址后文档就成了假的。**验收**：`docs/` 里不再出现具体默认值，改为引用函数名。
6. **面板：虚拟列表下的"全选"只作用于已渲染行**：>120 条走分块懒渲染，`#mem-list .mem-check` 只有已渲染的那些。**验收**：全选后计数等于筛选结果条数（需要把选中集合从 DOM 提到 S 状态）。

### P3 · 有空再说

7. 三个 4500 行量级模块（`growth.py` / `cli.py` / `memory.py`）按明确边界继续拆，不为行数而拆。
8. 首次体验：新用户第一屏的引导（初识流程已有，仍偏长）。
