### P2b · 情绪 / 心情（下一版候选，2026-11-20 排查后新增）

> 起因：用户问「心情满足怎么一直能满足？」。实测此刻是**平静**（valence 0.00 / arousal 0.10 / 强度 0%），但机制上确实有三个真问题：`满足` 是"正面低唤醒"的兜底桶、正向心境会粘一天多、七情从不自动生成。

8. **标签细化**：`_mood_label()` 现在只有 9 个标签，`valence ≥ 0.45 且 arousal < 0.35` 全部叫「满足」，中间没有"愉快/欣慰/平和/疲惫"这些档。加细档，并同步文档里的标签说明。**验收**：同一组事件下，低唤醒正面不再一律「满足」；新增 `tests/test_emotion_labels.py` 覆盖每档边界（含 ±0.15 / ±0.45 / arousal 0.35 / 0.6 这些临界值）。
9. **加门槛：没有正向事件在起作用就不许说「满足」**：`mood_now()` 返回的 `active` 为空、或正向事件权重已衰减到无实质影响时，强制回落「平静」；面板 `/api/overview` 与 `mood_brief()` 用同一口径。**验收**：清空情绪事件后 `emotion now` 与面板都显示「平静」；只剩一条权重 <0.02 的正面事件时也不显示「满足」。
10. **`extract` 顺带做一次轻量情绪评价**：现在七情只能靠显式 `emotion feel/evaluate/mirror` 写入，日常对话永远不产生情绪 → 心情长期静止、偶尔一条正面就跳「满足」（这才是"假"的根源）。让 `brain.py extract` 在封存对话时做极轻量极性判断（正/负/中性 + 强度），写成 emotion 事件；默认开、可配置关闭，失败不影响封存。**验收**：一段正常对话经 `extract` 后 `emotion list --days 1` 能看到 1–2 条自动事件，且 `emotion now` 的 label 会随对话内容变化。
