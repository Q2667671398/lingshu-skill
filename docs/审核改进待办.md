## §3 借鉴池

### 3.1 billion-context（`ranxianglei/billion-context`，★8446，TypeScript）

**它是什么**：给长期编码会话做**上下文压缩**的代理中间件，让 100K 窗口跑几十亿 token。

**核心机制**（论文 *Model-Driven Incremental Hierarchical Compression* 有完整论证）：

| 机制 | 内容 | 灵枢能否借 |
|---|---|---|
| **只压缩增量** | 每轮只压"自上次压缩以来新增的内容"，**绝不重写全史** | 部分已有：`consolidated` 标记让做梦只压未巩固的 ✅ |
| **多代分层** | block 带 tier∈{1,2,3}，摘要本身还能再被压成更高代 | 暂不借（见下） |
| **保护区** | 最近 5 条消息 / 5K token 不压；压缩工具调用本身硬保护 | 可借：灵枢注入时应有"绝不压缩区" |
| **需求侧触发** | 由模型判断何时该压，而非填满率阈值 | 不适用（灵枢不调 LLM） |
| **信息保留率** | 阈值式反复压缩按 ρ^k 几何衰减，**ρ≈0.4–0.6，四轮后只剩 3–13%** | **最值得借**：灵枢做梦也是反复合并，这个风险真实存在 |
| **前缀缓存友好** | 压缩不破坏 KV cache 前缀，缓存命中 96–99% | **值得借**：灵枢每轮注入若变动大，会打掉宿主的前缀缓存 |

**结论**：
- **立刻可做**：前缀缓存稳定性度量（§1 第 3 项）——现在完全没测，是盲区。
- **值得做**：把"信息保留率"思路用到做梦上，量化"合并多少轮后早期细节还剩多少"。
- **不借**：多代分层。灵枢的 `hippo/cortex/dust` 已是三层，`consolidated` 已做增量控制，
  再叠 tier 收益不明、复杂度大增。

### 3.3 古典算法（易经等）——**已结案**

只取结构，不取玄学。结论：

| 条目 | 结论 |
|---|---|
| 六爻位一致性检查 → `memory shape-audit` | ✅ **已做（v5.0）**。64 格签名 + 三条领域不变式（幻觉风险/高置信沉没/过期事实） |
| 盈不足术 → 标定 `charsPerToken` | ✅ **已做（`token-calib`）**，最小二乘拟合 `tokens = chars/ratio + overhead` |
| 四个变换算子 → `recall --robust` | ❌ 否决：召回鲁棒性靠多路召回+RRF 更直接，位运算算子只是换皮 |
| 六十甲子 → 双周期复习调度 | ❌ 否决：SM-2/FSRS 的间隔重复已有充分实证，周期表是找形状 |
| 卦辞/爻辞、吉凶判断、给记忆打"命运标签" | ❌ 明确不做：制造伪精度，破坏可解释性 |
| 把 384 当"覆盖全部可能性" | ❌ 是修辞不是事实：6 位只能区分 64 种状态 |

**最重要的实测结论**：字面上的易经谓词（当位/得中/有应）**在真实数据上没有区分力**
（违反率 100%/75%/74%）。所以 `shape-audit` 里换成了三条**领域不变式**——
它们能指向具体记录、能被人判对错，这才叫可用。
