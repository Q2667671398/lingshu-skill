## 二、必须修（P0）

### 问题一：清单生成会静默漏收新文件

**现象**

```
[manifest] manifest.json 与工作区不一致（如 ['docs/recovery.md', 'scripts/safety.py']）
```

这两个文件明明已在 `4b54619` 里提交，却不在 `manifest.json` 中。

**根因**（`scripts/make_manifest.py` 的 `scan_files()`）

它只收 **git 已跟踪** 的文件，未跟踪的一律跳过、且不报错：

```
新建 safety.py → 还没 git add → 跑 make_manifest → "成功，62 个文件"（其实漏了）
→ git add + commit → CI 看到 64 个文件 → 红
```

**证据**：修前 62 个文件，重新生成后 64 个，`git diff` 仅增加 8 行。

**影响**：任何"新增文件"的提交都会带出一张过期清单。清单是发布契约，一旦漏项，校验和与插件打包都不可信。

**建议（推荐二 + 三）**

- 一：把"未跟踪且未被忽略"的文件也计入并告警；
- 二：构建时若存在未跟踪候选文件，**直接失败**并提示先 `git add`——宁可本地红，不要等 CI；
- 三：把 `make_manifest.py --check` 加进 `pre-commit`。

**当前处置**：已重新生成（62 → 64），`--check` 通过；**未提交**。

## 四、结构性债（P2）

1. **单文件仍然过大**：`growth.py` 4546 / `cli.py` 4515 / `memory.py` 4322 行。已拆过两轮，方向对；下一轮只拆有明确边界的整块，别为行数而拆。
2. **异常吞没 327 处**：`except Exception` 是"失败即降级"的设计选择，有失败账本兜底是加分项；但关键路径（恢复、备份、元数据、锁）里吞异常会让真缺陷埋很久。建议关键路径除记账本外再做计数，让"最近七天吞了多少次"在 `doctor` 里可见。

4. **版本漂移没有自检**：`doctor` 的版本矩阵只查包内自洽，不查"已安装版和源码谁更新"。这正是护栏没生效却没人发现的直接原因。建议加一条发布漂移检查，不一致就给告警并给出升级命令。
5. **默认值写死在文档里**：`docs/mechanics.md` 那句"备份默认 `D:/brain-memory-backups`"在代码改成跨卷选址后仍然存在，直到昨天才被发现。建议默认值只在代码里定义一次，文档改为引用函数名。

## 五、已落地：高危指令护栏（`dsh-danger-guard`）

危险来自 shell，灵枢内部管不了，必须在 **DSH 工具层**拦。已按 DSH 原生扩展点实现并装机：

| 环节 | 实现 |
|---|---|
| 拦截点 | `tools/pre-execute` 瀑布（`dsh-tools` 的正式策略入口） |
| 分档 | 拒绝档：格式化磁盘、删盘符根、关机、删卷影副本；审批档：删除、移动、覆盖、`git clean`、强推 |
| 备份 | 真复制到 `~/.dsh/danger-guard/backups/<时间戳>-<随机>/`，含 `manifest.json` 与 `restore.ps1` |
| 审批 | 返回 `ask`，走 DSH 原生审批通道；会话策略为"从不询问"时自动拒绝（失败即关闭） |

**三条铁律**：备份失败即拒绝；解析不出备份目标（变量/通配符/管道）即拒绝；护栏自身异常则放行，不拖死工具链。

**实机验证**（会话策略为"从不询问"）：

```
变量路径删除   → 拒绝：无法确定要备份哪些路径，不能先备份
字面路径删除   → 先备份（payload.txt 16 字节已入包）→ 请求审批 → 拒绝 → 目标原样存在
普通命令       → 放行
```

备份还原已单测：删除目录 → 跑 `restore.ps1` → 文件与内容完整回来。

## 六、已落地：会话结束 / 项目结束自动写记忆

**决策：自动，不做手动。** 理由很直接——不能靠自觉，有的 AI 收尾时根本不写，靠人记也记不住。

实现挂在护栏同一个插件里：

```
agent/created → 该 agent 的 dispose 回调
  → brain.py work flush --skip-done   把未完成待办转成长期记忆
  → brain.py daily --force            写当日例行
```

三个设计要点：

1. **必须用 effect 挂载，且要有兜底**：`ctx.effect` 不存在时退回裸 `on('dispose')`，否则钩子静默失效——那又回到"靠自觉"。
2. **全部静默失败**：记忆库不可写、Python 缺失、超时，都不打扰会话结束。
3. **项目结束仍走 `checkpoint`**：子进程的当前目录不可靠，自动跑会写错项目，所以项目级收尾保持由模型显式调用（它本来就在技能收尾清单里）。

**验证状态**：链路已接线，但"会话真正结束时是否触发"无法在本会话内自证，需下一次会话结束观察。

## 七、这次踩出来的四条纪律

1. **PowerShell 5.1 的脚本必须带 UTF-8 BOM**。中文注释在无 BOM 时被按 GBK 解析，直接语法错误（`Unexpected token 'files'`）。任何给 PowerShell 5.1 跑的 `.ps1` 都要 BOM。
2. **改已安装插件的代码不会自动生效**。首次安装走热更新，改文件不重载；必须把插件关一次再开一次才装载新模块，否则会对着旧规则排错。
3. **规则宁窄勿宽**。第一版把 `Set-Content` 当"覆盖风险"，结果连正常写文件都被拦。破坏性判定必须区分"写"和"覆盖已有文件"，没有可靠判据时就不该拦。
4. **拦截是防误操作，不是安全沙箱**。它拦不住脚本、变量、程序内部的间接修改——文档里必须如实这么写，不能给虚假的安全感。

## 十三、记忆审核：规则闸 + 待审摘要（已定方案）

**问题**：自动写入的记忆没人复核（自动写 = 会话结束时模型已不在场），而全文审核很贵。

### 实测成本

| 项 | 实测 |
|---|---|
| 当前 startup 注入包 | 1283 字符 ≈ **640 tokens**（预算 1400） |
| 其中人格段 | 432 字符 = 216 tokens（约 2 字符/token） |
| 待审块塞全文（10 条 × 150 字） | +1500 字符 ≈ **+750 tokens**，注入预算几乎翻倍 |
| 待审块只给 id + 40 字要点 | +400 字符 ≈ **+200 tokens** |

### 方案：A + B 组合

**A. 写入前规则闸（0 token）**

在 `remember` / `work flush` / `daily` 的写入口做确定性校验：空内容、与近 7 天高度重复、含密钥特征、超长（>1200 字）、没有主语要素 → 直接标 `pending` 或拒绝写入。判断全在本地，不调用模型。

**B. 待审摘要注入（约 200 token，且只在有 pending 时出现）**

- 注入块**只给 `id` + 40 字要点 + 来源**，全文用 `recall <id>` 按需取；
- 下一会话开头看到清单，用 `review confirm` / `review discard` 处理；
- `review` 输出每行追加一句"建议动作"（保留/丢弃/合并），减少模型二次判断。

**C. 全文自审只在 75% 水位做梦时做**——那时本来就要压缩上下文，不额外付费。
**D. 本地小模型审核**（Ollama 0.6B）作为可选，不引入依赖。

### 落地清单

1. `pending_memory_reviews()` 增加 `--brief` 输出，注入层默认只取摘要；
2. `work flush` / `daily` 的产出默认 `review="pending"`；
3. `review` 每条加"建议动作"一行；
4. 文档写明：**审核窗口在下一会话开头，不在会话结束后**。

## 十四、灵枢内部的删除护栏（已确认方向，方案已按实测修正）

> 方向确认：**灵枢内部为主，同时保留 DSH shell 插件**（两层都留）。
> 但深入读代码后，原方案有一半是错的——必须先纠正，再动手。

### 实测修正：灵枢其实已经删得比想象中谨慎

| 命令 | 真实行为 | 确认 | 备份/反悔 |
|---|---|---|---|
| `forget <id>` | **已是软删除**：移入 dust 淡忘层，记录仍在 | 无需（可逆） | ✅ `revive` / `fold` / `unfold` 可捞回 |
| `memory purge <id>` | 物理删除，但已有**两道闸**：必须在 dust 层且 `forgotten_at` ≥ 7 天 + `--confirm` 手输 id 前 8 位 | ✅ 已有 | ❌ **无备份，删了就是删了** |
| `restore --exact` | 清受管文件 | ✅ 非交互必须 `--yes` | ✅ 恢复前自动备份 |
| `backup --keep` 修剪 | 直接 `unlink` 旧备份 zip | ❌ 无 | ❌ **无留档** |

**结论：真正缺的只有两处**——`purge` 物理删除前没有留底，`backup --keep` 修剪直接 unlink。
`forget` 已经是"可反悔"的形态（dust + revive），不需要再造一个 `trash/` 目录。

### 修正后的方案（更小、更准）

1. **`purge` 留底（软删除台账）**
   物理删除前，把完整记录追加进 `<记忆库>/trash.jsonl`（含 `deleted_at`、原始层、来源）。真删之后仍可从台账恢复；
   `trash restore <id>` 回写；`trash list` 查看；台账超过 90 天由 `daily` 清理。
   代价：一条记录几十到几百字节，比整库备份便宜得多。

2. **`backup --keep` 修剪改为"移走"**
   不再 `unlink`，改移到 `<备份目录>/.pruned/`，保留 7 天再清。这样"备份策略误配把好备份删光"也能救。

3. **统一确认入口（可选，第二步再做）**
   新增 `safety.confirm_destructive()`：TTY 下问一句并列出影响面，非 TTY 必须 `--yes`。
   目前 `restore` 自己写了一份确认逻辑，`purge` 用 confirm token——两套并存可以工作，统一是锦上添花，不是刚需。

### 执行顺序（按用户答复）

**备份 → 问 → 执行；用户拒绝时，把刚做的那份备份删掉。**

理由：先备份才能在"问"的时候把备份路径一起给用户看；拒绝就清理，不留下无用备份垃圾。
（注意：清理的必须是**本次新建**的那份，不能碰历史备份。）

## 十五、协作流程约定（自本次起）

用户明确要求，后续所有改动按这个顺序走，不要直接动手：

1. **先调研**——查代码、查外部做法，拿到证据；
2. **出方案**——写清改什么、影响面、风险，落到本类文档或对话里；
3. **问确认**——向用户复述"我理解的是不是这个意思"，等待明确同意；
4. **再实现**——同意后才改代码，改完给出验证结果。

## 十六、第二轮全项目排查：漏洞 / Bug / 缺点 / 维护问题

> 方法：读代码 + 针对性检索，标 **已验证** 的都有代码位置；标 **待复核** 的是合理怀疑、尚未跑实验。
> 先说结论：**没有发现可直接远程利用的漏洞**，问题集中在"默认值不安全""已知未修""结构性债"三层。

### 一、安全与威胁模型

**先说做对的部分（避免误报，也避免以后改坏）**

- 面板只监听 `127.0.0.1`，且有**随机 token + Host/Origin 双校验**，`/api/*` 统一在入口处拦截（`panel_server.py` L618、L843）；环境变量给空 token 时**拒绝启动**而不是退化成不设防。
- `restore` 有 zip-slip 防护（绝对路径与 `..` 都会抛错），并做临时目录 + 逐文件原子替换。
- 备份包会剥掉 `panel.cloud` 的 token，并跳过 `.env`/`*.key`/`*.pem`/含 `secret` 的文件。
- 全项目**没有** `shell=True`、`eval`、`exec`、`pickle.loads`、不安全的 `yaml.load`。

| 编号 | 问题 | 严重度 | 状态 |

| 安-1 | **IM 群聊护栏默认 `shadow: true`——只记日志不拦**。任何群成员都能触发 `forget`/`dream`/`backup` 等敏感命令，实际防护为零，除非用户手工把 `shadow` 改 false。这是"默认值不安全"，比没有护栏更危险（以为有） | 高 | ✅ **已修（v3.46）**：默认改 `false`，观察模式须显式 `shadow: true` 且启动会 warn |

### 四、运维与使用体验

- **面板无常驻方案**：`brain.py serve` 随终端/会话结束而死，没有服务化（Windows 服务/计划任务）的官方做法。
- **备份成功没有"跨卷"确认**：`pick_backup_dir()` 会静默挑一块别的盘，但不会在输出里明确说"本次备份跨卷，可抵御整盘丢失"。
- **memory 审核闭环没接上**：`pending` 标记存在、`review` 命令存在，但自动写入（`work flush` / `daily`）产出的记忆是否标 pending 未确认——这直接关系到第十三节的方案能否落地。

### 五、建议优先级

1. **先改默认值**：`lingshu-guard` 的 `shadow` 默认改 false（或首次启动强制提示一次），这是唯一"以为有防护其实没有"的问题。
2. **补 XSS 转义**：面板是唯一能渲染记忆原文的地方，成本低、风险实在。
3. **修锁泄漏**：一行清理逻辑，长跑进程迟早踩到。
4. **审核闭环**：按第十三节落地（规则闸 + 摘要待审）。
5. **工程债**：覆盖率 → 性能基线 → 副本合并，按季度推进，不要一次性动。
